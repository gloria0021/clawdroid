## Clarifications

### Session 2026-11-24

- Q: ファイルで直したい点 → A: ガチのコードエディターのように見やすくしたい（行番号・色分け）。ファイルマネージャーではなくファイルツリーで辿る（PC は左にツリー・右にコード）
- Q: スマホでの並べ方 → A: ツリーを左から引き出すパネルにする。コードは常に画面いっぱいで、左端からのスワイプ（またはタイトルバーのボタン）でツリーが重なって出る。会話の画面のサイドパネルと同じ操作。大画面ではツリーを左に置きっぱなしにする（2026-11-24 マスター提案で、1 画面ずつの切り替え案から変更）
- Q: ファイルの作成・削除・名前の変更は要るか → A: 要る。スマホで `.env` を作って API キーを埋めることがよくある（002 では範囲外だったものを本仕様で入れる）。`.env` は一例で、ファイルが作れればよい
- Q: 作成・削除・名前の変更の手段 → A: ターミナルの仕組み（Gateway の管理者の権限）を使う。Gateway への API の追加は待たない
- Q: Esc で強制終了できるか → A: できない。Esc は文字（ESC）を送るだけで、シェルやふつうのコマンドは止まらない。止めるのは Ctrl+C（割り込み）。Esc で取り消すのは vim や一部の対話型ツールが独自に決めているだけ。よって強制終了は Ctrl+C を 1 回で送れる手段として足す

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 走っているコマンドをすぐ止める (Priority: P1)

マスターはターミナルで走り続けるコマンド（ログの追跡、止まらないビルドなど）を、1 回の操作で止める。
今は Ctrl を押してから c を打つ 2 段の操作で、キーボードを出していないと止められない。

**Why this priority**: 止められないコマンドは、ターミナルを開き直すしかなくなる。逃げ道としてのターミナル（002 US4）の価値を直接損なう。

**Independent Test**: `sleep 100` や `tail -f` を実行し、キーボードを閉じたまま特殊キーの行の操作 1 回で止まり、プロンプトに戻ることを確かめる。外付けキーボードの Ctrl+C でも止まることを確かめる。

**Acceptance Scenarios**:

1. **Given** コマンドが走っている, **When** 特殊キーの行の「^C」を押す, **Then** 割り込みがシェルに送られ、コマンドが止まってプロンプトに戻る（キーボードの表示は不要）
2. **Given** 外付けキーボードをつないでいる, **When** Ctrl+C を押す, **Then** 同じく割り込みが送られる（コピーにはならない）
3. **Given** 大量の出力が流れている, **When** 「^C」を押す, **Then** 押した反応がすぐに返り、割り込みが遅れずに届く

---

### User Story 2 - 外付けキーボードでコピーと貼り付け (Priority: P2)

マスターは外付けキーボードで、PC の端末と同じ Ctrl+Shift+C で選んだ文字をコピーし、Ctrl+Shift+V で貼り付ける。
キーボードの無いときは、特殊キーの行から貼り付けられる。

**Why this priority**: PC の端末と同じ手の動きで使えると、タブレットや折りたたみでの作業が速い。止める（P1）の次に頻度が高い。

**Independent Test**: 外付けキーボードで出力の一部を選んで Ctrl+Shift+C を押し、別のアプリに貼り付けて一致することを確かめる。別のアプリでコピーした文字を Ctrl+Shift+V で貼り付け、シェルに入ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 出力の一部を選んでいる, **When** Ctrl+Shift+C を押す, **Then** 選んだ文字がクリップボードに入り、選択が解ける
2. **Given** 何も選んでいない, **When** Ctrl+Shift+C を押す, **Then** 何も起きない（割り込みは送らない）
3. **Given** クリップボードに文字がある, **When** Ctrl+Shift+V を押す, **Then** その文字がシェルに入力される（複数行でも、改行ごとに実行されず 1 回の貼り付けとして扱われる。シェルが対応している場合）
4. **Given** 外付けキーボードが無い, **When** 特殊キーの行の「貼り付け」を押す, **Then** Ctrl+Shift+V と同じく貼り付けられる
5. **Given** クリップボードが空、または文字ではない, **When** 貼り付けを行う, **Then** 何も入力しない

---

### User Story 3 - 開いたときに OpenClaw の看板を出す (Priority: P3)

マスターがターミナルを新しく開くと、最初に本家 OpenClaw の CLI と同じマスコットとロゴのアスキーアートが出て、そのあとにシェルのプロンプトが続く。

**Why this priority**: 体験の仕上げ。機能の価値は増えないが、OpenClaw の道具だと一目で分かる。

**Independent Test**: ターミナルを新しく開き、アスキーアートが崩れずに出たあとプロンプトが出ることを確かめる。縦持ちのスマホ、横持ち、タブレットのそれぞれで崩れないことを確かめる。アプリを離れて戻ったときに、もう一度出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** ターミナルを新しく開く, **When** シェルにつながる, **Then** プロンプトより前に、マスコットとロゴ（OPENCLAW の文字）のアスキーアートが表示される
2. **Given** 画面の桁数がマスコットとロゴを横に並べるのに足りない, **When** 表示する, **Then** マスコットの下にロゴを置くなど、折り返して崩れる形にはならない。ロゴも入らない幅ならマスコットと「OpenClaw」の文字だけを出す
3. **Given** 開いたままのターミナルに戻る（つなぎ直し・取り戻し）, **When** 表示する, **Then** アスキーアートは出し直さない
4. **Given** アスキーアートが出ている, **When** シェルの出力が続く, **Then** アスキーアートは普通の出力と同じく上へ流れ、スクロールで遡れる。シェルの入力や履歴には入らない

### User Story 4 - ファイルツリーとコードを並べて見る (Priority: P2)

マスターはファイルを「フォルダを 1 段ずつ開くファイルマネージャー」ではなく、PC のコードエディターのような**ファイルツリー**で辿る。
フォルダはその場で開閉でき、開いた階層は覚えている。スマホではコードが常に画面いっぱいに出て、ツリーは左から引き出すパネル（会話の画面のサイドパネルと同じ）。左端からスワイプすればいつでもツリーに戻れる。
大画面（タブレット・折りたたみを開いた状態）では、ツリーが左に出たまま、右にコードが並ぶ。

**Why this priority**: エージェントの成果物を確かめるとき、複数のファイルを行き来する。1 段ずつ降りて戻る今の形では、行き来のたびに階層を辿り直す。

**Independent Test**: 作業フォルダでファイルを開き、フォルダを 3 つその場で展開してファイルを 2 つ行き来する。スマホでは左端のスワイプでツリーが出て、閉じても展開の状態が残っていること、タブレットではツリーとコードが並んで見え、ツリーを押すと右のコードだけが替わることを確かめる。

**Acceptance Scenarios**:

1. **Given** ファイルを開く, **When** 画面が出る, **Then** 作業フォルダの最上位がツリーで出る。フォルダの行を押すと、その場で中身が字下げされて開く（画面は移らない）。もう一度押すと閉じる
2. **Given** 大画面, **When** ツリーのファイルを押す, **Then** 右のペインにそのファイルが出て、ツリーはそのまま残り、開いているファイルの行が選ばれた見た目になる
3. **Given** スマホでツリーのパネルを開いている, **When** ファイルを押す, **Then** パネルが閉じてそのファイルのコードが画面いっぱいに出る
4. **Given** ツリーを開いた状態でアプリを離れる・画面を回す, **When** 戻る, **Then** 展開していたフォルダと開いていたファイルが残っている
5. **Given** 開いているファイル, **When** コードの画面を見る, **Then** 上にツリーの中でのパス（どのフォルダの中か）が示される
6. **Given** スマホでコードを見ている, **When** 左端からスワイプする（またはタイトルバーのツリーのボタンを押す）, **Then** ツリーのパネルが重なって出る。展開の状態とスクロール位置は前回のまま。パネルの外を押す・戻る操作（予測型「戻る」を含む）・左へのスワイプで閉じる
7. **Given** スマホでファイルをまだ開いていない, **When** ファイルの画面を開く, **Then** ツリーのパネルが開いた状態で出る

### User Story 5 - コードエディターのように読み書きする (Priority: P2)

マスターはコードを、PC のコードエディターと同じ見え方で読む・直す。左に行番号、文法に沿った色分け、今の行の強調があり（行へ移る操作は入れない）、編集中も色分けが消えない。

**Why this priority**: 今は読むときだけ色分けされ、行番号が無く、編集に入ると素の文字になる。「何行目のどこ」が分からないと、エージェントとのやり取り（「42 行目を直して」）にも使えない。

**Independent Test**: 300 行ほどのコードを開き、行番号と色分けが出ること、編集に入っても色分けと行番号が残ること、カーソルのある行が強調されること、折り返しの切り替えで長い行が横スクロールになることを確かめる。

**Acceptance Scenarios**:

1. **Given** コードのファイルを開く, **When** 表示する, **Then** 左端に行番号が並び、本文は文法に沿って色分けされる。行番号はスクロールしても本文の行とずれない
2. **Given** 編集に入る, **When** 文字を打つ, **Then** 色分けと行番号は消えず、打った内容に合わせて更新される。カーソルのある行は背景で強調される
3. **Given** 長い行がある, **When** 折り返しを切り替える, **Then** 「折り返す / 折り返さず横にスクロール」が替わる。行番号は折り返した行の先頭にだけ付く
5. **Given** 編集している, **When** 取り消し・やり直しの操作をする, **Then** 直前の変更が戻る・進む
6. **Given** 編集している, **When** キーボードの上の記号の行からインデント（Tab）や括弧・記号を押す, **Then** その文字が入る（ソフトウェアキーボードで打ちにくい記号の近道）

### User Story 6 - ファイルを作る・消す・名前を変える (Priority: P2)

マスターはスマホから作業フォルダに `.env` を作り、API キーを書き込んで保存する。いらないファイルを消し、名前を変える（`.env.example` を写して `.env` にする、など）。

**Why this priority**: エージェントに秘密の値を渡さずに、手元で鍵を置ける。会話に API キーを書くと記録に残るため、ファイルを直接作れることに安全上の価値がある。

**Independent Test**: ツリーから作業フォルダの最上位に `.env` を作り、1 行書いて保存し、Gateway 側でファイルができていることを確かめる。名前を `.env.local` に変え、最後に消して、ツリーと Gateway の両方から無くなることを確かめる。

**Acceptance Scenarios**:

1. **Given** ツリーのフォルダ（または最上位）, **When** 「新しいファイル」を選んで名前を入れる, **Then** 空のファイルができ、ツリーに現れ、そのまま編集できる状態で開く
2. **Given** ツリーのフォルダ, **When** 「新しいフォルダ」を選んで名前を入れる, **Then** フォルダができ、ツリーに現れる
3. **Given** 同じ名前がもうある, **When** 作る・名前を変える, **Then** 上書きせず、その名前が使われていることを示して入れ直させる
4. **Given** ファイルの行を長押しする, **When** 「名前を変更」を選んで新しい名前を入れる, **Then** 名前が変わり、開いていればそのまま新しい名前で開いている
5. **Given** ファイルかフォルダの行を長押しする, **When** 「削除」を選ぶ, **Then** 確認（名前と、フォルダなら中身ごと消えること・元に戻せないこと）が出て、承認したときだけ消える
6. **Given** 保存していない変更のあるファイル, **When** 削除・名前の変更をしようとする, **Then** 先に変更を保存するか捨てるかを確かめる
7. **Given** `/` を含む・`..` を含む・空の名前, **When** 確定しようとする, **Then** 確定できず、理由が示される（作業フォルダの外へは作れない・動かせない）
8. **Given** Gateway がこの端末にファイルの作成・削除・名前の変更を許していない, **When** ツリーを見る, **Then** それらの操作は出ない（読む・直すはこれまで通り）

### Edge Cases

- 割り込みを送ってもコマンドが止まらない場合（割り込みを無視するプログラム）: アプリは強制的に殺さない。何度でも送れる。止まらなければ利用者がシェルの操作で対処する
- シェルが終了している・つながっていないときに「^C」「貼り付け」を押した場合: 何も送らず、操作は無効の見た目にする
- 非常に長い文（数千行）を貼り付ける場合: 取りこぼさずに送り、表示が固まらない
- 貼り付ける文に制御文字が混ざっている場合: 貼り付けとして扱い、意図しない操作キーとして解釈させない（シェルが対応している範囲で）
- Ctrl を押した状態（特殊キーの行の Ctrl）で外付けキーボードの Ctrl+C を押した場合: 割り込みを 1 回だけ送る
- 文字サイズを 200% にした場合: アスキーアートは桁数に合わせて形を選び、崩れない
- 外付けキーボードのない端末: Ctrl+Shift の操作は使えないが、特殊キーの行で同じことができる
- 非常に多くのファイルがあるフォルダ（node_modules など）を展開した場合: 少しずつ読み込み、ツリーのスクロールがカクつかない
- 深い階層を展開した場合: 字下げが画面幅を食い尽くさない（一定の深さから先は字下げを増やさない、または横にスクロールできる）
- 数千行のファイル: 行番号と色分けを付けてもスクロールがカクつかない。色分けは画面に見えている範囲から先に行い、終わる前でも読める
- 色分けの種類が分からないファイル: 行番号だけ付けて素の文字で出す
- 編集中に別のファイルを押した場合: 保存していない変更があれば、捨てるか確認する（002 FR-010）
- エージェントが同じファイルを同時に作った・消した場合: 作るときにもう在れば「使われている」と示す。消したあとに開いていれば、ツリーを取り直してそのことを示す
- 作業フォルダの中のシンボリックリンクの先が外を指している場合: その先への作成・削除・名前の変更は行わない
- `.env` などの秘密の値を含むファイル: 保存していない変更を端末に残すときも、バックアップ・機種変更の引き継ぎに含めない
- 削除の途中で接続が切れた場合: 消えたかどうかをツリーの取り直しで確かめてから示す（消えたと決めつけない）

## Requirements *(mandatory)*

### Functional Requirements

**強制終了（割り込み）**

- **FR-001**: アプリ MUST、特殊キーの行に、割り込み（Ctrl+C）を 1 回の操作で送る「^C」を置く。キーボードの表示に関係なく押せる
- **FR-002**: アプリ MUST、外付けキーボードの Ctrl+C を割り込みとして送る（コピーに割り当てない）
- **FR-003**: アプリ MUST NOT、Esc を割り込みとして扱わない。Esc は今まで通り ESC を送る

**コピーと貼り付け**

- **FR-010**: アプリ MUST、外付けキーボードの Ctrl+Shift+C で、選んでいる出力の文字をクリップボードに入れる。選択が無いときは何もしない
- **FR-011**: アプリ MUST、外付けキーボードの Ctrl+Shift+V で、クリップボードの文字をシェルへ貼り付ける
- **FR-012**: アプリ MUST、特殊キーの行に「貼り付け」を置き、Ctrl+Shift+V と同じ貼り付けを行う
- **FR-013**: アプリ MUST、貼り付けを、シェルが対応していれば「貼り付け」として送り、複数行が 1 行ずつ実行されないようにする
- **FR-014**: アプリ MUST、コピーできたことを通知（Snackbar）で示す

**開いたときの看板**

- **FR-020**: アプリ MUST、ターミナルを新しく開いたときだけ、シェルの出力より前に本家 OpenClaw の CLI と同じマスコットとロゴのアスキーアートを表示する
- **FR-021**: アプリ MUST、桁数に応じてアスキーアートの形を選ぶ（横に並べる / マスコットの下にロゴ / マスコットと「OpenClaw」の文字だけ）。どの形でも行が折り返さない
- **FR-022**: アプリ MUST、アスキーアートをシェルに送らない（画面に描くだけ。シェルの入力・履歴・Gateway 側の記録に入らない）
- **FR-023**: アプリ MUST、つなぎ直し・取り戻しではアスキーアートを出し直さない
- **FR-024**: アプリ MUST、マスコットの色はアプリのテーマの強調色、ロゴは既定の文字色で描く（ターミナルの既定の配色に従う。002 FR-029）。動かさない（本家の CLI は動かすが、開いたときの演出は入れない。AGENTS.md 2.8）

**ファイルツリー**

- **FR-040**: アプリ MUST、ファイルの一覧をツリーで示し、フォルダをその場で開閉できるようにする（1 段ずつ画面を移る形をやめる）。並びは 002 FR-003 のまま（フォルダが先、名前順）
- **FR-041**: アプリ MUST、スマホではツリーを左から引き出すパネルにし、左端からのスワイプとタイトルバーのボタンの両方で開けるようにする（スワイプだけに頼らない。TalkBack からも開ける）。大画面ではツリーを左に出したままにする。パネルの見た目と出し入れの動きは会話の画面のサイドパネルにそろえる
- **FR-045**: アプリ MUST、パネルを開くスワイプが、コードの横スクロール（折り返さない表示）とぶつからないようにする。コードが横にスクロールできる間は横スクロールを優先し、左端に着いてからのスワイプ、または画面の左端からのスワイプでパネルを開く
- **FR-042**: アプリ MUST、展開しているフォルダ・開いているファイル・ツリーのスクロール位置を、戻る操作・構成の変更・プロセスの終了を越えて残す
- **FR-043**: アプリ MUST、開いているファイルをツリーの中で選ばれた見た目にし、コードの側にそのパスを示す
- **FR-044**: アプリ MUST、エージェントのワークスペースへの切り替え（002 FR-002）をツリーでも保つ

**コードエディター**

- **FR-050**: アプリ MUST、テキストのファイルの左端に行番号を示す。行番号は本文の行とずれず、等幅で、本文より目立たない色にする（`onSurfaceVariant`）
- **FR-051**: アプリ MUST、読むときも編集中も、文法に沿った色分けを保つ（今の「編集中は色分けしない」をやめる）
- **FR-052**: アプリ MUST、編集中、カーソルのある行を背景で強調する
- **FR-053**: アプリ MUST、折り返す / 折り返さず横にスクロール を切り替えられるようにし、選んだ方を覚える
- **FR-054**: （削除。行へ移る操作は入れない。マスター指定 2026-11-24）
- **FR-055**: アプリ MUST、編集中の取り消し・やり直しを提供する
- **FR-056**: アプリ MUST、編集中、ソフトウェアキーボードの上に、インデント（Tab）と打ちにくい記号（括弧・引用符・記号）を入れる行を出す
- **FR-057**: アプリ MUST、色分け・行番号を付けても、数千行のファイルのスクロールと入力がカクつかないようにする（AGENTS.md 2.8 の 0）

**作成・削除・名前の変更**

- **FR-060**: アプリ MUST、作業フォルダの中で、ファイルとフォルダを新しく作れるようにする。作ったファイルは編集できる状態で開く
- **FR-061**: アプリ MUST、作業フォルダの中のファイルとフォルダの名前を変えられるようにする（同じフォルダの中での名前の変更。別のフォルダへの移動は範囲外）
- **FR-062**: アプリ MUST、作業フォルダの中のファイルとフォルダを、確認のあとで削除できるようにする。確認には名前と、フォルダなら中身ごと消えること、元に戻せないことを示す（`AlertDialog`）
- **FR-063**: アプリ MUST、既にある名前への作成・名前の変更を上書きせずに断る
- **FR-064**: アプリ MUST、名前を検証し、`/`・`..`・空・制御文字を含む名前を受け付けない。どの操作も作業フォルダの外（シンボリックリンクの先を含む）に及ばないようにする
- **FR-065**: アプリ MUST、エージェントのワークスペースと作業フォルダの外では、作成・削除・名前の変更を出さない（読むだけのまま）
- **FR-066**: アプリ MUST、Gateway がこの端末に許している手段でだけこれらの操作を行い、許されていなければ操作を出さない。Gateway の権限を広げない（002 FR-030）
- **FR-067**: アプリ MUST、操作のあとツリーを取り直し、結果を通知（Snackbar）で示す。失敗したら理由を示す
- **FR-068**: アプリ MUST、`.env` などの秘密の値を含むファイルの、保存していない変更を、クラウドのバックアップと機種変更の引き継ぎに含めない。保存できたら端末に残る下書きを消す
- **FR-069**: アプリ MUST、作業フォルダに端末のファイルをアップロードできるようにする。入口はフォルダの長押しのメニューの「アップロード」（最上位は一覧の下の空白の長押し）。端末のファイル選択で複数を選べ、同じ名前があればまとめて「上書き・別名で保存・飛ばす」を確かめる。1 ファイル 12 MB まで（Gateway の `terminal.upload` でホストの一時置き場に置き、シェルで目的のフォルダへ移す。置く先は 1 つの名前として確定し、確定できない環境では置かない）。進み・中止・結果（容量の上限を超えたものは名前を挙げる）はダウンロードと同じ透過効果の帯で示す（マスター指定 2026-11-26、CJ レビュー）

**共通**

- **FR-030**: アプリ MUST、特殊キーの行に足すキーも、48dp 以上の押せる範囲・TalkBack の読み上げ・ガラスのピルの見た目（AGENTS.md 2.7・2.10・2.11）に従う。行に収まらないときは横にスクロールできる

### Key Entities

- **ファイルツリー**: ルート・展開しているフォルダの集まり・開いているファイル・スクロール位置
- **ファイルの操作**: 作成（ファイル / フォルダ）・名前の変更・削除。対象のパス・新しい名前・結果
- **エディターの表示設定**: 折り返すか。端末に覚える
- **特殊キーの行**: Esc・Tab・Ctrl・矢印（既存）に、^C・貼り付けを加えたもの
- **看板**: マスコット（20 桁 × 10 行）とロゴ（47 桁 × 3 行）。横に並べると 71 桁。出すのはターミナルを新しく開いたときの 1 回だけ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 走っているコマンドを、キーボードを閉じた状態から操作 1 回で止められる（10 回中 10 回）
- **SC-002**: 「^C」を押してからコマンドが止まるまで、手元のネットワークで 0.5 秒以内
- **SC-003**: 外付けキーボードで、コピーと貼り付けが PC の端末と同じキーで 10 回中 10 回成功する
- **SC-004**: 100 行の文を貼り付けて、1 行も欠けず、途中で実行されない（対応するシェルで）
- **SC-005**: 縦持ちのスマホ・横持ち・タブレット、文字 100% / 200% のすべてで、アスキーアートの行が折り返さない
- **SC-007**: 3 階層下の別のフォルダのファイルへ、開いているファイルから 3 回以内の操作で移れる
- **SC-008**: 3,000 行のファイルを行番号・色分け付きで開き、スクロールと入力にカクつきが目で見て分からない
- **SC-009**: 開いてから 1 秒以内に、画面に見えている範囲の色分けが終わる
- **SC-010**: ツリーから `.env` を作って 1 行書き、保存できたことが示されるまでを 1 分以内に終えられる
- **SC-011**: 作業フォルダの外を指す名前・パスでの作成・削除・名前の変更が、10 回中 10 回断られる
- **SC-006**: ターミナルを開いてから入力できるまでの時間が、アスキーアートを足す前より長くならない（002 SC-007 の 3 秒以内を保つ）

## Assumptions

- 利用者はマスター 1 人。外付けキーボードはタブレット・折りたたみ・スマホにつないで使うことがある
- 割り込みは端末の慣例どおり Ctrl+C（ETX）を送ることで行う。シグナルを直接送る手段は Gateway に求めない
- Ctrl+C を割り込み、Ctrl+Shift+C/V をコピー・貼り付けにする割り当ては、Linux の主な端末アプリの慣例に合わせる
- 特殊キーの行の Ctrl と c の組み合わせ（既存）は残す。「^C」はその近道
- アスキーアートは本家 OpenClaw（同じエコシステムのオープンソース）の CLI と同じもの。ライセンスの表示が必要なら、既存のライセンス表示に加える
- 本家 CLI の、日替わりの一行（タグライン）や版の表示は出さない（看板の絵だけ）
- スマホの縦持ちで上下に分割（上にツリー・下にコード）する案は採らない。縦長でもコードが半分の高さ（20 行前後）しか見えず、ツリーも窮屈になる。引き出すパネルなら、コードは常に全面、ツリーはスワイプ 1 回で出る
- 左端からのスワイプは、端末のジェスチャーの「戻る」と同じ場所を使う。会話の画面のサイドパネルと同じ扱いにし、どちらでも同じ感覚で使えるようにする。ジェスチャーの「戻る」とぶつかって開きにくい端末でも、タイトルバーのボタンで開ける
- ファイルの作成・削除・名前の変更は本仕様で入れる（002 の前提を変更）。アップロードと別のフォルダへの移動は範囲外
- Gateway のファイルの API（2026.11.6 時点）は、既にあるファイルの読み書きだけで、作成・削除・名前の変更を持たない（Control UI の資料にも「エディターは作成・削除しない」とある）。そのため、これらはターミナルと同じ管理者の権限の範囲で行う前提になる。ターミナルが許されていない Gateway では出ない。計画の段階で、手段（ターミナルの仕組みを使うか、Gateway 側への機能の追加を待つか）と、作業フォルダの外に出ない守り方を決める
- 削除は Gateway 側にごみ箱が無いため元に戻せない。Git で管理されているファイルは Git から戻せるが、`.env` のように Git の外のファイルは戻せない。確認の文でそのことを示す
- 補完・定義へのジャンプ・複数のタブ・ミニマップなど、IDE の重い機能は範囲外（持ち歩きの道具。憲章 VII）
- 色分けは承認済みの部品（002 research R10）を使い続ける
