## User Scenarios & Testing *(mandatory)*

### User Story 1 - アプリを閉じていても応答の完了を知る (Priority: P1) 🎯 MVP

マスターがエージェントに依頼してアプリを閉じ、別のことをしていても、応答が終わると通知が出る。通知にはエージェントの名前・会話の名前・応答の冒頭が出て、押すとその会話が開く。

**Why this priority**: 持ち歩きの道具として最も価値が高い。長い作業を頼んで画面を閉じ、終わったら戻る、という使い方ができないと、画面を開いたまま待つしかない（憲章 VII）。

**Independent Test**: 依頼を送ってホーム画面に戻り、応答の完了から数秒以内に、エージェント名・会話名・応答の冒頭を含む通知が出ること。押すとその会話が開き、応答が見えること。

**Acceptance Scenarios**:

1. **Given** 常駐がオンで、アプリが裏にある・閉じている, **When** エージェントの応答が完了する, **Then** エージェント名・会話名・応答の冒頭を含む通知が出る
2. **Given** 通知が出ている, **When** 押す, **Then** アプリが開き、その会話のその応答が見える位置で開く
3. **Given** マスターがその会話を画面で開いている, **When** 応答が完了する, **Then** 通知は出さない（ほかの会話の応答は通知する）
4. **Given** 同じ会話で応答が続けて完了する, **When** 通知を見る, **Then** 通知は 1 つにまとまり、最新の内容に更新される
5. **Given** 複数のエージェントから応答が届く, **When** 通知を見る, **Then** エージェントごとにまとまり、それぞれ別に開ける
6. **Given** 常駐している, **When** 通知の欄を見る, **Then** 目立たない常駐の通知が 1 つあり、接続の状態（つながっている / つなぎ直している）だけが示される。押すとアプリが開く

---

### User Story 2 - 承認を通知の上で済ませる (Priority: P1)

エージェントが Gateway の承認（コマンドの実行の許可など）を待っているとき、アプリを閉じていても通知が出る。通知には承認を求める内容の全文（実行しようとしているコマンド・作業フォルダ・どのエージェントか）が出て、通知のボタンで「1 回だけ許可」「常に許可」「拒否」を選べる。アプリを開かずに作業を先へ進められる。

**Why this priority**: 承認待ちは放っておくと作業が止まったままになる。外出先で通知を見てその場で許可できれば、頼んだ作業が止まらない。内容を確かめずに許可するのは危ないので、全文を通知の中で読めることが前提。

**Independent Test**: 承認が要るコマンドをエージェントに実行させてアプリを閉じ、承認待ちの通知にコマンドの全文が出ること、通知のボタンで許可するとエージェントの作業が続き、拒否すると止まることを確かめる。

**Acceptance Scenarios**:

1. **Given** アプリが裏にある・閉じている, **When** Gateway が承認を求める, **Then** 承認待ちの通知が出る。通知を広げると、承認を求める内容の全文（コマンド・作業フォルダ・エージェント名・会話名）が等幅で読める
2. **Given** 承認待ちの通知, **When** 「1 回だけ許可」「常に許可」「拒否」のどれかを押す, **Then** アプリを開かずにその決定が Gateway に送られ、通知が結果（許可した・拒否した）に変わってから消える
3. **Given** 端末がロックされている, **When** 通知の許可・拒否のボタンを押す, **Then** 端末のロックを解除してからでないと決定は送られない（ロック画面のまま他人に許可されないように）
4. **Given** 承認待ちの通知が出ている, **When** ほかの端末（PC など）で承認・拒否される・期限が切れる, **Then** 通知は消える
5. **Given** 決定を送れなかった（接続が切れている・もう解決済み）, **When** ボタンを押した, **Then** 送れなかった理由が通知に示され、押すとアプリの承認の画面が開く
6. **Given** 内容が長い（長いコマンド・複数行）, **When** 通知を広げる, **Then** 端末が通知に出せる範囲で全文を出す。収まらなければ末尾に「続きはアプリで」と示し、押すとアプリの承認の画面で全文が読める

---

### User Story 3 - 自動化の失敗を知る (Priority: P2)

自動化（定期実行）が失敗したとき、アプリを閉じていても通知で知る。

**Why this priority**: 失敗は気づかないと翌日まで直せない。

**Independent Test**: 失敗する自動化を走らせ、失敗の通知が出て、押すとその自動化の詳細が開くことを確かめる。

**Acceptance Scenarios**:

1. **Given** アプリが裏にある, **When** 自動化の実行が失敗する, **Then** 自動化の名前と失敗を示す通知が出て、押すとその自動化の詳細が開く

---

### User Story 4 - 通知と常駐を設定する (Priority: P3)

マスターは設定画面で、常時接続のオン・オフ、通知の種類（応答・承認待ち・自動化の失敗）ごとのオン・オフを選ぶ。通知が届かないときの原因（通知の許可・電池の最適化）もここで分かる。ロック画面での表示は端末の設定に任せる（2026-11-26）。

**Why this priority**: 既定のままでも US1〜3 は動く。調整と困ったときの手がかり。

**Independent Test**: 常駐をオフにしてアプリを閉じると常駐の通知が消え、応答の通知も来なくなること。種類ごとのオフで、その種類だけ来なくなること。テストの通知が出ること。

**Acceptance Scenarios**:

1. **Given** 設定画面, **When** 常時接続をオフにする（初期値）, **Then** 常駐の通知が消え、アプリが裏に回って 60 秒たつと接続を休む。アプリを閉じているあいだは通知が来ない（開いているあいだと、裏に回って 60 秒以内は来る）
2. **Given** 設定画面, **When** 応答の通知をオフにする, **Then** 応答の通知は来ず、承認待ち・失敗の通知は来る
3. **Given** 通知の許可が無い, **When** 設定画面を開く, **Then** 「通知設定」のスイッチはオフに見える。オンにすると許可を求め、拒否されたら端末の通知の設定を開く
4. **Given** 常時接続がオンで、電池の最適化の対象になっている, **When** 設定画面を見る, **Then** 通知が遅れることがあると示し、最適化から外す導線を出す（常時接続がオフなら行を出さない）
5. **Given** 設定画面, **When** 通知のテストを押す, **Then** 本物の応答の通知と同じ形（既定のエージェントの顔・名前）でテストの通知が出る
6. **Given** エージェントごとに音を変えたい, **When** 端末の通知の設定を開く, **Then** エージェントごとの項目（チャンネル）があり、端末の設定で音・オン・オフを変えられる

---

### Edge Cases

- 常駐中に接続が切れた: 自動でつなぎ直し、常駐の通知は「つなぎ直している」に変わる。切れていたあいだに完了した応答は、つなぎ直したあとにまとめて通知する（同じ会話は 1 つ）
- 短時間に大量の応答: 同じ会話は 1 つにまとめて更新し、通知が並び続けない
- 応答が長い: 冒頭だけを出し、Markdown の記号は取り除いた文にする。画像・ファイルだけの応答は「画像」などの種類を示す
- 実行が中断・失敗で終わった: 応答の完了としては通知しない（失敗は会話の中で分かる）。ただし途中の文があればそれを通知する
- 自分が送った文の反映（自分の送信）: 通知しない
- ほかの端末（PC の Control UI）で開いている会話: その端末の状態は分からないので通知する
- 接続先を切り替えた・接続情報を消した: 常駐を止め、前の接続先の通知を消す
- 端末の再起動: 常時接続がオンならアプリを開かなくても再開する（端末の制限で開くまで再開できない場合は、その旨を設定画面に示す）。オフならつながない
- 常時接続がオフで裏に回った: 60 秒で接続を休む。前に戻るとつなぎ直し、裏にいたあいだに終わった応答は通知せず未読の点で示す
- 通知の許可を後から取り消した: 常駐の通知も含めて出せないので、設定画面の「通知設定」のスイッチをオフに見せる。接続はアプリを開いているあいだだけになる

## Requirements *(mandatory)*

### Functional Requirements

**常駐**

- **FR-001**: アプリ MUST、常駐がオンのとき、アプリが裏にある・閉じているあいだも Gateway との接続を保つ（常駐の通知を伴う Android のフォアグラウンドサービス）
- **FR-002**: 常駐の通知 MUST、目立たない重要度で、接続の状態（つながっている / つなぎ直している）だけを示し、押すとアプリが開く
- **FR-003**: アプリ MUST、常駐（常時接続）を設定でオン・オフできるようにする。初期値はオフ（電池のため。2026-11-26 改訂。以前はオン）。オフのとき、アプリ MUST、裏に回って 60 秒で Gateway との接続を休み、前に戻ったらつなぎ直す。承認待ちがある・ダウンロード中は休まない。アプリのプロセスが起きただけ（前にない・常時接続がオフ・承認待ちもダウンロードも無い）ではつながない
- **FR-004**: アプリ MUST、裏にあるあいだは Gateway から受け取るイベントを通知に要るもの（応答の完了・承認待ち・自動化の失敗）に絞り、応答を文字ごとに流すイベントで電池を使わない。画面に戻ったら差分を取り直す（001 FR-122）
- **FR-005**: アプリ MUST、接続が切れたら自動でつなぎ直し、切れていたあいだに完了した応答をつなぎ直したあとに通知する

**応答の通知**

- **FR-010**: アプリ MUST、エージェントの応答の完了を通知する。通知はエージェント名・会話名・応答の冒頭（Markdown の記号を除く）を含む
- **FR-011**: アプリ MUST NOT、マスターが画面で開いている会話の応答を通知しない
- **FR-012**: アプリ MUST、同じ会話の通知を 1 つにまとめて更新し、エージェントごとにまとめる
- **FR-013**: 通知を押すと、アプリ MUST、その会話のその応答が見える位置で開く
- **FR-014**: （削除。通知からの返信は入れない。2026-11-24 マスター指定）

**承認待ち・自動化の失敗**

- **FR-020**: アプリ MUST、Gateway の承認待ちを通知し、ほかで解決された・期限が切れたら通知を消す
- **FR-022**: 承認待ちの通知 MUST、承認を求める内容の全文（コマンド・作業フォルダ・エージェント名・会話名）を、広げた通知の中で等幅で読めるようにする。端末が出せる範囲を超える分は「続きはアプリで」と示す
- **FR-023**: 承認待ちの通知 MUST、Gateway が受け付ける決定（1 回だけ許可・常に許可・拒否）のボタンを持ち、押すとアプリを開かずに決定を送る。送ったあとは結果を示してから通知を消す。送れなかったら理由を示し、押すとアプリの承認の画面を開く
- **FR-024**: アプリ MUST、端末がロックされているあいだは通知のボタンから決定を送らない（ロックの解除を求める）
- **FR-025**: 承認待ちの通知を押す（ボタン以外）と、アプリ MUST、承認の画面を開く
- **FR-021**: アプリ MUST、自動化の実行の失敗を通知し、押すとその自動化の詳細に進めるようにする

**設定**

- **FR-030**: アプリ MUST、通知の種類（応答・承認待ち・自動化の失敗）ごとにオン・オフできるようにする
- **FR-031**: アプリ MUST、エージェントごとに通知のチャンネルを分け、音・オン・オフを端末の設定で変えられるようにする
- ~~**FR-032**~~: 2026-11-26 削除。ロック画面での内容の出し方は端末の設定に任せ、アプリの項目は置かない。アプリ MUST、端末が内容を伏せるときに出す題だけの公開版を通知に付ける
- **FR-033**: アプリ MUST、通知の許可・電池の最適化・常駐の状態を設定画面に示し、足りないものには導線（許可を求める・端末の設定を開く）を出す。通知の許可は設定の画面の「通知設定」のスイッチで示して求め（許可が無ければオフに見え、オンにすると求める）、別の行は置かない。電池の最適化は常時接続がオンのときだけ出す（2026-11-27 改訂。以前は通知の画面のいちばん上に許可の行）
- **FR-034**: アプリ MUST、通知のテストを設定画面から行えるようにする。テストの通知は本物の応答の通知と同じ形（既定のエージェントの顔・名前・チャンネル）にする（2026-11-26）
- **FR-035**: アプリ MUST、通知と常駐の設定を、AGENTS.md の設定画面の規則（`ListItem` ＋ `Switch` を 1 画面に縦に並べる）で示す

### Key Entities

- **常駐の状態**: オン・オフ（設定）、接続の状態（つながっている / つなぎ直している / 休んでいる / 止まっている）、止まっている理由（許可が無い・オフ・接続情報が無い）。休んでいる = 常時接続がオフで裏にいるあいだ（`ConnectionState.Paused`）
- **応答の通知**: エージェント・会話・応答の識別子・冒頭の文・時刻。会話ごとに 1 つ
- **承認待ちの通知**: 承認の識別子・内容の全文（コマンド・作業フォルダ）・エージェント・会話・期限・選べる決定。承認ごとに 1 つ
- **通知の設定**: 常時接続のオン・オフ、種類ごとのオン・オフ。端末内に保つ（既存の設定の項目を使う）
- **エージェントのチャンネル**: エージェントごとの通知の種類分け（音・オン・オフは端末の設定）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: アプリを閉じた状態で、応答の完了から通知の表示まで、通常 5 秒以内（001 SC-010）
- **SC-002**: 常駐オン・電池の最適化から外した状態の 24 時間の待ち受けで、応答の完了の 99% 以上が通知される（001 SC-011）
- **SC-003**: 画面で開いている会話の応答では、10 回中 10 回、通知が出ない
- **SC-004**: 承認待ちの通知のボタンで送った決定が、10 回中 10 回、Gateway に届いてエージェントの作業が続く・止まる（接続できているとき）
- **SC-007**: 承認を求められてから、通知のボタンで許可するまでを、アプリを開かずに 10 秒以内で済ませられる
- **SC-005**: 常駐による電池の消費が、待ち受け 1 時間あたり端末全体の 2% 以下（001 SC-013 に合わせる）
- **SC-006**: 同じ会話で 10 回続けて応答が完了しても、通知の欄に並ぶのはその会話の 1 つだけ

## Assumptions

- 利用者はマスター 1 人。接続先の Gateway は 1 つ
- 方式は OpenClaw 公式 Android アプリと同じ（常駐 + 端末内で通知を作る）。外部の Push サービス（FCM など）・中継サーバー・Gateway のプラグインは使わない
- Gateway の生存確認（25 秒ごとの ping）はアプリ側で変えられない。電池の消費は受け取るイベントを絞って抑える（001 Assumptions）
- フォアグラウンドサービスの種類（Play ストアの申告に要る）は plan で決める（公式アプリは connectedDevice）
- 設定の項目（常時接続・種類ごとのオン・オフ）は既存の設定の保存先に既にある。画面と動きを本仕様で作る（ロック画面の項目は 2026-11-26 に削除）
- 範囲外（Web UI で行う・今回は入れない）: 通知からの返信（001 FR-104 を外す）、Push 方式、通知の時間帯（おやすみ）設定、ほかの端末と既読を同期すること、エージェント以外のイベント（チャンネルのメッセージなど）の通知
