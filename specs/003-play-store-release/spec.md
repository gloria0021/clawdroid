## User Scenarios & Testing *(mandatory)*

### User Story 1 - 署名したリリース版を作り、テストの配布に載せる (Priority: P1)

マスターは手元で 1 つの手順を実行するだけで、署名済みの配布用パッケージを作り、Play Console のテスト配布にアップロードできる。
テスターは Play ストアから入れ、Debug 版と同じようにすべての機能を使える。

**Why this priority**: これが無いと何も公開できない。ポリシー対応や掲載情報は、この上に乗る。

**Independent Test**: 配布用パッケージを作って内部テストに上げ、テスト用の端末で Play ストアから入れて、接続・会話・送信・ファイル・ターミナル・自動化・ダウンロード・音声入力・テーマの切り替えを一通り操作し、落ちないこと・Debug 版と同じ見た目と動きであることを確かめる。

**Acceptance Scenarios**:

1. **Given** アップロード用の鍵が手元にある, **When** リリース版を作る手順を実行する, **Then** 署名済みの配布用パッケージ（App Bundle）ができる。鍵と合言葉はリポジトリに含まれない
2. **Given** アップロード用の鍵が無い環境（別の開発機・CI）, **When** 同じ手順を実行する, **Then** 鍵が無いことを示して止まり、未署名のものを配布用として出さない
3. **Given** 前回アップロードした版がある, **When** 次の版を作る, **Then** 版の番号は前回より必ず大きくなる
4. **Given** 配布用の版を入れた, **When** 主要な機能を一通り使う, **Then** 縮小・難読化による欠落（起動時の落ち・保存した設定の読み込み失敗・ターミナルの表示失敗）が無い
5. **Given** Debug 版が入っている端末, **When** リリース版を入れる, **Then** 別のアプリとして並んで入り、互いのデータに影響しない

### User Story 2 - Play のポリシーに沿った状態で審査を通す (Priority: P1)

マスターは、権限・フォアグラウンドサービス・データの扱い・対象年齢・審査用のアクセス手段をそろえた状態で審査に出し、差し戻しなく通す。

**Why this priority**: 使っていない権限の宣言や申告の食い違いは差し戻しの典型的な理由。公開の可否を直接決める。

**Independent Test**: 配布用パッケージの権限一覧と Play Console の申告（データ セーフティ・フォアグラウンドサービス・権限の用途）を突き合わせ、すべて一致していること、審査担当が説明だけで主要な画面まで到達できることを確かめる。

**Acceptance Scenarios**:

1. **Given** 配布用パッケージ, **When** 宣言された権限を一覧にする, **Then** 実際に使う機能に対応するものだけが残っている
2. **Given** フォアグラウンドサービスを使う, **When** Play Console で申告する, **Then** 種類ごとに、利用者に見える用途と、それを示す短い動画・説明がそろっている
3. **Given** データ セーフティの申告, **When** アプリの実際の通信先・保存するデータと比べる, **Then** 食い違いが無い（開発者のサーバーへの送信が無いこと、音声は端末の音声認識に渡すこと、接続情報は端末内で暗号化して持つこと）
4. **Given** 審査担当がアプリを開く, **When** Play Console の「アプリへのアクセス」の説明に従い、審査専用の Gateway の接続先とトークンを入れる, **Then** 接続を済ませて会話の画面まで到達できる
5. **Given** プライバシーポリシー, **When** ストアの掲載とアプリ内から開く, **Then** 同じ公開ページが開き、日本語と英語で読める

### User Story 3 - ストアの掲載ページを整える (Priority: P2)

利用者は Play ストアでアプリを見つけ、何をするアプリか・何が必要か（自分の OpenClaw Gateway）を、掲載ページだけで理解して入れるかを判断できる。

**Why this priority**: 公開そのものには最低限の掲載情報で足りるが、「自分の Gateway が要る」と伝わらないと、入れてすぐ消す利用者と低評価が増える。

**Independent Test**: 掲載ページのプレビューを、OpenClaw を知っている人と知らない人に見せ、何のアプリか・入れる前に何が要るかを 30 秒以内に答えられることを確かめる。

**Acceptance Scenarios**:

1. **Given** 掲載ページ, **When** 日本語と英語の端末で開く, **Then** それぞれの言語で、名前・短い説明・詳しい説明・スクリーンショットが表示される
2. **Given** 詳しい説明, **When** 読む, **Then** 自分の OpenClaw Gateway が必要なこと、接続できる経路（同じネットワーク・Tailscale 等）、OpenClaw の公式アプリではないことが書かれている
3. **Given** スクリーンショット, **When** 見る, **Then** スマホとタブレットのそれぞれで、会話・サイドパネル・ファイル・ターミナル・設定の実際の画面が、ライトとダークの両方を含めて並ぶ。個人の情報（実在のセッション名・トークン・パス）は写っていない

### User Story 4 - 設定の「このアプリについて」で情報・プライバシーポリシー・ライセンスを確かめる (Priority: P2)

利用者は設定の「このアプリについて」で、アプリの版と動いている環境を確かめ、不具合の報告用にまとめてコピーできる。
同じ場所から、プライバシーポリシーとオープンソースのライセンスを開ける。

**Why this priority**: プライバシーポリシーをアプリ内から開けることと、同梱したライブラリの許諾文を表示することは、公開時に満たすべき義務。版と環境の情報は、公開後の問い合わせへの対応に要る（マスター指定 2026-11-24 で P3 から上げた）。

**Independent Test**: 設定の「このアプリについて」を開き、版の名前と番号がストアの表示と一致すること、コピーした情報に接続先・トークンが含まれないこと、プライバシーポリシーが開くこと、同梱したすべてのライブラリ・フォント・アイコンの許諾文が読めることを確かめる。

**Acceptance Scenarios**:

1. **Given** 設定の画面, **When** 「このアプリについて」まで下る, **Then** アプリ名・版の名前と番号・接続中の Gateway の版・Android の版・端末の機種が表示される（未接続なら Gateway の版は「未接続」）
2. **Given** 「このアプリについて」, **When** 「情報をコピー」を押す, **Then** 上の情報が文字としてコピーされ、コピーしたことが Snackbar で示される。接続先の URL・トークン・セッション名は含まれない
3. **Given** 「このアプリについて」, **When** 「プライバシーポリシー」を押す, **Then** 今の表示の言語の公開ページが、アプリ内のブラウザで開く
4. **Given** 「このアプリについて」, **When** 「オープンソースのライセンス」を押す, **Then** 新しい画面で、同梱したライブラリ・フォント・アイコンが名前順の一覧で出る。各行には名前と許諾の種類が表示される
5. **Given** ライセンスの一覧, **When** 行を押す, **Then** 共通のボトムシートで許諾文の全文が読める。長い文はシートの中の面だけがスクロールする
6. **Given** ネットワークにつながっていない, **When** ライセンスを開く, **Then** 端末内に同梱した文で読める（ネットワークに頼らない）

### User Story 5 - 段階的に公開し、更新を出し続ける (Priority: P3)

マスターはテストの配布で確かめてから本番に出し、本番は少しずつ広げる。次の版を出しても、利用者の設定・接続情報・下書きは消えない。

**Why this priority**: 初回の公開後に毎回発生する流れ。初回の公開そのものは US1・US2 で成り立つ。

**Independent Test**: 版 A を入れて接続・設定・下書きを作った端末に、版 B を Play ストアから更新で入れ、すべてが残っていることを確かめる。

**Acceptance Scenarios**:

1. **Given** テストの配布で確かめた版, **When** 本番に出す, **Then** 利用者の一部から段階的に広げられ、問題があれば広げるのを止められる
2. **Given** 前の版を使っている利用者, **When** 新しい版に更新する, **Then** 接続情報・設定・下書き・読んでいた位置が残り、再接続なしで使い続けられる
3. **Given** 新しい版を出す, **When** 変更点を書く, **Then** 日本語と英語の「新機能」の文が添えられる
4. **Given** 公開までの段取り, **When** 進める, **Then** 内部テスト → （アカウントの条件で必要なら）クローズドテスト → 本番の段階的な公開、の順に進む

### Edge Cases

- アップロード用の鍵をなくした: Play App Signing を使い、アップロード用の鍵は Play Console で再登録できる状態にしておく。アプリの署名の鍵そのものは Google 側で持つ
- 縮小・難読化で、実行時にしか使わない部分（保存データの読み書き・暗号化・ネイティブのターミナル表示）が消える: リリース版で主要な機能を一通り動かす確認を、毎回の版の必須の手順にする
- 端末内のデータベースの形が版の間で変わる: 移行を用意し、移行できない場合でも接続情報と設定は残す（キャッシュは作り直してよい）
- Android 12 以下の端末: ストアで対象外として表示され、入れられない（最小 API 33）
- 平文の通信の許可について審査で問われる: 公開の経路では暗号化（wss://）を求め、平文はプライベートアドレス・Tailscale の宛先だけにアプリ側で限っていることを説明できるようにする
- 権限を外したことで既存の機能が動かなくなる: 権限を外す前に、その権限を使うコードが無いことを確かめる
- 審査担当が Gateway に到達できない: 差し戻しの典型。審査の期間中は審査専用の Gateway を止めない。止まっていたら差し戻しを受けてから立て直すのではなく、審査に出す前に外の回線から接続を確かめる
- 審査専用の Gateway が悪用される: ターミナル・ファイル・外部への送信を無効にし、使い捨ての環境で動かす。審査が済んだらトークンを変える
- ライブラリを足したのにライセンスの一覧に無い: 一覧は依存関係から自動で作り、手で書き足すのはフォント・アイコンなど依存関係に出ないものだけにする
- 端末の言語が日本語・英語以外: 既定の言語で表示する（下の多言語対応を参照）
- 文字 200% で、ライセンスの全文や情報の行が切れる: 折り返して全文を読めるようにする
- 名前「SumahoClaw」と OpenClaw の関係: 公式アプリと誤解される表現（公式のロゴ・「OpenClaw 公式」）を掲載ページとアイコンに使わない

## Requirements *(mandatory)*

### Functional Requirements

**ビルドと署名**

- **FR-001**: ビルド MUST、1 つの手順で署名済みの App Bundle を作れるようにする。署名の鍵と合言葉はリポジトリの外（手元の設定・環境変数）から読み、リポジトリに含めない
- **FR-002**: ビルド MUST、署名の情報が無いときは配布用の生成を失敗させ、理由を示す（Debug 版の生成は妨げない）
- **FR-003**: 版の番号 MUST、アップロードのたびに単調に増える。版の名前は利用者に見せる形（例: 1.0.0）にする。どちらも 1 か所で管理する

**ポリシー**

- **FR-010**: 配布用パッケージ MUST、使っている機能に対応する権限だけを宣言する。使っていない `FOREGROUND_SERVICE_CONNECTED_DEVICE`・`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`・`CHANGE_NETWORK_STATE` は、対応する機能を今回の版に含めないなら外す

- **FR-018**: 審査専用の Gateway MUST、マスターの Gateway とは別の使い捨ての環境で動かし、暗号化した経路（wss://）で外から到達できるようにする。ターミナル・ファイルの操作・外部への送信は無効にし、見本のエージェント・会話・自動化を用意する。審査の期間中は動かし続け、審査が済んだらトークンを変える
- **FR-019**: 審査専用の Gateway の隔離 MUST、次を守る。(1) マスターの Gateway とは別のコンテナで、設定・状態・トークンを分け、ホストのディレクトリをつながない (2) ターミナル・ファイルの操作・外部への送信を切り、見本のエージェントは道具を持たない会話だけにする (3) モデルの API キーは審査専用に作り、使える金額の上限を低く決める（安いモデルを使う） (4) 外へは Cloudflare Tunnel の `wss://` だけで出し、ルーターのポートは開けない (5) 審査に出す前に、外の回線（携帯の回線など）から接続して会話の画面まで届くことを確かめる
- **FR-036**: レポジトリ MUST、公開する前に OSS の許諾（`LICENSE`）を置き、README に許諾の種類を書く。許諾は MIT（マスター決定 2026-11-25。取り込んだ OpenClaw のコード・`reference/openclaw/` の資料と同じ）
- **FR-037**: 公開する前 MUST、履歴を含めて出してはいけないものが無いか確かめる。秘密情報（鍵・トークン・パスワード）、`memory/`（`.gitignore` に入れる）、コミットの作者のメールアドレス（GitHub の noreply に書き換える。マスター決定 2026-11-25）、`reference/` に写した外部の資料の許諾
- **FR-038**: 公開したあと MUST、Issues を受け付け、プライバシーポリシーの問い合わせ先（「このページを公開している GitHub のレポジトリの Issues」）がこのレポジトリを指すようにする

**多言語対応**

- **FR-050**: 利用者に見える文言 MUST、すべて文言のリソースに置き、コードに直書きしない（001 FR-094 の確認を公開の条件にする）
- **FR-051**: 対応する言語 MUST、OpenClaw の Control UI と同じ 22 言語を目標に、次の 3 段階で広げる。既定の言語（端末の言語に対応が無いときに出す言語）は英語にする

  - 段階 2: ロシア語・イタリア語・ポーランド語・ウクライナ語・トルコ語・オランダ語・スウェーデン語・インドネシア語・ベトナム語・タイ語・ヒンディー語
  - 段階 3: アラビア語・ペルシア語（右から左に書く言語。左右反転した画面、特に左端のスワイプ・右上のピル・高速スクロールバーを確かめてから）
- **FR-052**: 対応するすべての言語 MUST、アプリの文言・ストアの掲載情報（名前・短い説明・詳しい説明）・新機能の文をそろえる。スクリーンショットは段階 1 の言語だけを用意し、ほかは英語を出す。プライバシーポリシーは日本語と英語だけにする（Play が求めるのは 1 つの URL）
- **FR-056**: 日本語以外の文言 MUST、ふだんの開発では書かず、ストアリリースのスクリプトを走らせたときだけ作る。前回から変わった文言だけを訳し、訳は Release のビルドだけが使う。Debug のビルドは日本語だけでよい
- **FR-057**: 日本語以外の言語（特に中国語・韓国語・タイ語・ヒンディー語） MUST、その文字を正しい字形で表示できるフォントで出す。既定の LINE Seed JP は日本語にだけ使い、ほかの言語ではシステムのフォントを既定にする
- **FR-058**: 文字が長くなる言語（ドイツ語・フランス語など） MUST、文字 200% でも切れ・重なりが無いことを、段階 1 の言語ごとに確かめる
- **FR-053**: 翻訳の漏れ MUST、リリース版の生成で検出し、対応する言語に訳の無い文言があれば生成を失敗させる
- **FR-054**: 日付・時刻・数・件数 MUST、表示の言語の書き方（並び順・区切り・複数形）に従う
- **FR-055**: Gateway に送る文（再起動の理由など）と、Gateway が返す文（エージェントの応答・エラーの本文）は翻訳しない。Gateway に送る文は言語によらない英語に揃える
