# Feature Specification: アプリのショートカット（ランチャーの長押しメニュー）

**Feature Branch**: `007-app-shortcuts`（ブランチは切らず main で進める）

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: "ここのショートカットって設定で動的に変えられたりする？例えばキノに聞く（ホーム）、Moonshotに依頼(SumahoClaw)とかを自由に差し替えたり" / "セッションも指定できたりする？もちろんセッションはアーカイブや削除あり得るからその場合は動的ショートカットから消してほしい"

## Clarifications

### Session 2026-11-25

- Q: 長押しメニューの項目を設定で差し替えられるか → A: できる。Android の動的ショートカット（`ShortcutManagerCompat`）で、設定で選んだ内容をそのまま反映する
- Q: 行き先にセッションを指定できるか → A: できる。行き先は「エージェントのホーム」「作業フォルダで新しい会話」「既存のセッション」の 3 種類
- Q: アーカイブ・削除されたセッションのショートカット → A: 動的ショートカットから外す。外すのは、アプリが持つセッションの一覧にその変化が反映された時点（変更イベント・一覧の読み込み）。外すためだけの読み込みは足さない
- Q: 押したときに、行き先のセッションがまだあるかを確かめるか → A: 確かめない。待たずにすぐ開く（反応を優先。マスター指定 2026-11-25）。アーカイブ済みは読むだけで開き、削除済みは空の会話で開く。削除済みの会話に送ると、Gateway が同じキーで新しいセッションを作る。それでよい（マスター指定 2026-11-25。Gateway 2026.11.6 の `chat.send` は見つからないセッションを作り直す。dist で確認、実機での送信は未確認）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - よく使う行き先をホーム画面から 1 回で開く (Priority: P1) 🎯 MVP

マスターがホーム画面で SumahoClaw のアイコンを長押しすると、「キノに聞く」「Moonshotに依頼」のような項目が出る。押すと、そのエージェントのホーム・その作業フォルダの新しい会話・決めておいたセッションが、入力できる状態ですぐ開く。

**Why this priority**: アプリを開いてサイドパネルからエージェントと会話を選ぶ手間を、1 回の長押しに縮める。持ち歩きの道具としての速さに直結する。

**Independent Test**: 設定でショートカットを 1 つ以上作り、ランチャーのアイコンを長押しすると、その名前と顔のアイコンで項目が出ること。押すと決めた行き先が開くこと。

**Acceptance Scenarios**:

1. **Given** ショートカットを設定している, **When** ランチャーの SumahoClaw のアイコンを長押しする, **Then** 設定した順に、名前とエージェントの顔のアイコンで項目が出る
2. **Given** 行き先が「エージェントのホーム」, **When** 項目を押す, **Then** そのエージェントのホームの会話が開く
3. **Given** 行き先が「作業フォルダで新しい会話」, **When** 項目を押す, **Then** そのエージェント・その作業フォルダの新しい会話が、入力欄に書ける状態で開く（セッションは最初の送信で作られる。既存の新しい会話と同じ）
4. **Given** 行き先が「既存のセッション」, **When** 項目を押す, **Then** そのセッションが開く
5. **Given** アプリが閉じている・裏にある・別の会話を開いている, **When** 項目を押す, **Then** どの場合も同じ行き先が開く（通知から開くときと同じ経路）
6. **Given** 項目を押してアプリが開いた, **When** 戻る, **Then** 通常どおりの戻り方をする（ショートカット専用の戻り方を作らない）

---

### User Story 2 - ショートカットを設定で差し替える (Priority: P1)

マスターは設定画面でショートカットの枠を並べ、枠ごとにエージェント・行き先・名前を選ぶ。足す・外す・並べ替えると、ランチャーの長押しメニューにすぐ反映される。

**Why this priority**: US1 の中身を決める手段。固定の項目では使い方の変化に追いつかない。

**Independent Test**: 設定で枠を足す・外す・並べ替える・名前を変えるたびに、ランチャーの長押しメニューがその内容に変わること。

**Acceptance Scenarios**:

1. **Given** 設定画面のショートカットの欄, **When** 枠を足し、エージェントと行き先を選ぶ, **Then** 枠が並び、ランチャーの長押しメニューに項目が増える
2. **Given** 行き先に「既存のセッション」を選ぶ, **When** セッションを選ぶ, **Then** そのエージェントのアクティブなセッションから選べる（アーカイブ済みは出さない）
3. **Given** 枠を作った, **When** 名前を見る, **Then** 行き先から付けた名前が初期値として入っている（ホーム = エージェント名、作業フォルダ = フォルダ名、セッション = セッション名）。マスターは書き換えられる（例: 「キノに聞く」）
4. **Given** 名前を書き換えていない「既存のセッション」の枠, **When** そのセッションの名前が変わる, **Then** ショートカットの名前も追いかけて変わる
5. **Given** 枠が並んでいる, **When** 並べ替える・外す, **Then** ランチャーの長押しメニューの順番・項目が同じように変わる
6. **Given** 枠が上限（4。多くのランチャーが長押しメニューに出せる数）に達した, **When** 足そうとする, **Then** 足せない理由を示す

---

### User Story 3 - 消えた会話のショートカットを自動で片付ける (Priority: P2)

ショートカットの行き先のセッションがアーカイブ・削除されたら、マスターが何もしなくても、ランチャーの長押しメニューからその項目が消える。

**Why this priority**: 片付けないと、もう使わない会話が長押しメニューに残り続ける。ただし押しても大きな害はない（US1 のとおり開ける）ので P2。

**Independent Test**: ショートカットにしたセッションを、アプリ・PC の Control UI のそれぞれでアーカイブ・削除し、アプリがその一覧を持っている状態で長押しメニューから項目が消えること。

**Acceptance Scenarios**:

1. **Given** 行き先のセッションをアプリでアーカイブ・削除した, **When** ランチャーの長押しメニューを見る, **Then** その項目は無い
2. **Given** アプリを開いている, **When** ほかの端末で行き先のセッションがアーカイブ・削除される, **Then** その変化を受け取った時点で項目が消える
3. **Given** アプリが止まっているあいだに、ほかの端末で行き先のセッションがアーカイブ・削除された, **When** 項目を押す, **Then** その会話がそのまま開き（アーカイブ済みは読むだけ、削除済みは空の会話）、一覧が読み込まれた時点で項目が消える
4. **Given** 行き先がアーカイブで外れた枠, **When** 設定画面を見る, **Then** 枠は残り「アーカイブ済み」と示される。アーカイブを戻すと、ランチャーの項目も戻る
5. **Given** 行き先が削除で外れた枠, **When** 設定画面を見る, **Then** 枠は無い
6. **Given** 行き先のエージェントが Gateway の設定から消えた, **When** エージェントの一覧が更新される, **Then** そのエージェントの枠をすべて外す

---

### Edge Cases

- 削除済みの会話に送る: Gateway が同じキーで中身の無い新しいセッションを作る。片付けで外れた枠は戻らない（Clarifications）
- 並行開発（ワークツリー）の会話を削除した直後に送る: Gateway が後始末を終えるまで同じキーの作り直しを断るので、送信の失敗として既存の表示で示す
- ショートカットをホーム画面に置いた（ランチャーの機能で項目をドラッグ）: 動的ショートカットから外してもホーム画面の項目は残るので、外すときに無効にし、押すと理由（アーカイブ・削除された）を示す
- 未接続のときに項目を押す: アプリはその行き先で開き、接続を待つ（既存の会話の画面と同じ）
- 接続先を切り替えた・接続情報を消した: すべての枠とランチャーの項目を消す（前の Gateway の会話を指したままにしない）
- 言語の切り替え: 名前はマスターが書いた文字列か会話名なので訳さない。無効にした理由の文言は `strings.xml` から作り直す
- エージェントの顔の画像が無い・取れない: ランチャーのアイコンには SumahoClaw のアイコンを使う
- 文字サイズ 200%: 設定画面の枠の行が崩れない（ランチャーの表示は端末の責任）

## Requirements *(mandatory)*

### Functional Requirements

**ショートカットの中身**

- **FR-001**: アプリ MUST、設定した枠を Android の動的ショートカットとして、設定した順に登録する（`ShortcutManagerCompat`。マニフェストの静的ショートカットは使わない）
- **FR-002**: 枠 MUST、エージェント・行き先・名前を持つ。行き先は「エージェントのホーム」「作業フォルダで新しい会話」「既存のセッション」のどれか
- **FR-003**: 項目のアイコン MUST、エージェントの顔の画像を丸く切り抜いたもの（adaptive icon）。取れなければ SumahoClaw のアイコン
- **FR-004**: 項目の名前 MUST、短い名前（ランチャーの表示）と長い名前（ランチャーが長い名前を出すとき）を持つ。マスターが書き換えていなければ行き先から作り、セッション名が変わったら追いかける
- **FR-005**: 枠の数 MUST、4 を上限とする（多くのランチャーが長押しメニューに出せる数。`getMaxShortcutCountPerActivity()` は登録できる数で、出せる数ではないため使わない。端末がそれより少なければそちらに合わせる）

**押したとき**

- **FR-010**: 項目を押すと、アプリ MUST、その行き先を開く。開く経路は通知から開くときと同じもの（Intent の extras → `OpenTarget` → `ForegroundState.open`）を使う
- **FR-011**: アプリ MUST NOT、押したときに行き先がまだあるかを Gateway に問い合わせて待たない。すぐ開く
- **FR-012**: 押したことをランチャーに知らせる（`reportShortcutUsed`。ランチャーの並べ方の学習に使われる）

**片付け**

- **FR-020**: アプリ MUST、アプリが持つセッションの一覧が変わるたびに枠と照らし合わせ、行き先がアーカイブ・削除された項目を動的ショートカットから外す
- **FR-021**: アプリ MUST NOT、片付けのためだけにセッションの一覧を読み込まない（一覧の読み込みは既存の契機: そのエージェントを開く・サイドパネルを開く・接続し直す・ショートカットから開く）
- **FR-022**: 外すとき、アプリ MUST、ホーム画面に置かれた同じ項目を無効にし、理由の文言を付ける
- **FR-023**: アーカイブで外れた枠 MUST、設定に残し、アーカイブが戻されたらランチャーに戻す。削除で外れた枠 MUST、設定から消す。エージェントが消えたら、そのエージェントの枠を消す
- **FR-024**: 一覧をまだ読み込んでいないエージェントの枠 MUST、その状態のまま残す（読み込んでいないことを「消えた」と扱わない）

**設定**

- **FR-030**: アプリ MUST、設定画面に「ショートカット」の行を置き、押すと枠の一覧の画面を開く（既存の 設定 → エージェント・通知 と同じ 1 段の画面）。枠は `ListItem` で縦に並べ、枠ごとにエージェントの顔・名前・行き先を示す
- **FR-031**: 枠の作成・編集（エージェント・行き先・セッション・名前を選ぶ）は MUST、ボトムシートで行う（AGENTS.md 2.7 の短い補助表示）。階層の深いサブ画面を作らない
- **FR-032**: アプリ MUST、枠を並べ替え・外せるようにする。長押しで開く操作には `onLongClickLabel` を付ける
- **FR-033**: 枠の設定 MUST、端末内に保つ（既存の設定の保存先）。プロセスの終了・構成の変更を越えて残す
- **FR-034**: 利用者向けの文言 MUST、`app/src/main/res/values/strings.xml`（日本語）に置く

### Key Entities

- **ショートカットの枠**: 識別子（ショートカットの ID）・順番・エージェント ID・行き先の種類・作業フォルダ（作業フォルダのとき）・セッションのキー（セッションのとき）・マスターが付けた名前（無ければ空）・状態（有効 / アーカイブ済み）
- **行き先（`OpenTarget`）**: ホームと既存のセッションは既存の `Session(agentId, sessionKey)`（ホームは枠を作るときにホームの会話のキーを覚える）。「作業フォルダで新しい会話」を開くものだけを足す

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ランチャーで項目を押してから、行き先の画面が出るまで、アプリが裏にあるときは 1 秒以内、閉じているときは通常の起動と同じ時間
- **SC-002**: 設定で枠を変えてからランチャーの長押しメニューに反映されるまで、1 秒以内（ランチャーの再読み込みを除く）
- **SC-003**: アプリが一覧を持っている状態でのアーカイブ・削除は、10 回中 10 回、長押しメニューから項目が消える
- **SC-004**: 押したときに、行き先の確認のための待ち（読み込み表示）が出ない

## Assumptions

- 利用者はマスター 1 人。接続先の Gateway は 1 つ
- 「キノに聞く（ホーム）」の「ホーム」はエージェントのホームの会話、「Moonshotに依頼（SumahoClaw）」の「SumahoClaw」は作業フォルダ（プロジェクト）と解釈した
- ホーム画面に置かれた項目を無効にする（FR-022）のは、「消してほしい」の意図に沿うと判断した仮置き。無効にせず開けるままにする選択もある
- Gateway の挙動（削除済みのキーへの `chat.send` で作り直す）は OpenClaw 2026.11.6 の配布物で確認した。版が変わったら確かめ直す
- 範囲外: アプリからホーム画面に項目を置かせる操作（`requestPinShortcut`）、最近の会話を自動で項目にすること（`pushDynamicShortcut`）、ウィジェット、Quick Settings のタイル
