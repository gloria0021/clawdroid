## User Scenarios & Testing *(mandatory)*

### User Story 1 - ファイルを辿って読む (Priority: P1)

マスターは会話を開いたまま、そのセッションの作業フォルダのファイルを一覧で辿り、開いて読む。
コードは等幅・色分けで、画像は全画面で拡大して見られる。エージェントのワークスペースにも切り替えて、同じように読める。

**Why this priority**: エージェントの成果物をスマホで確かめる用途がいちばん多い。編集・ダウンロードはこの上に乗る。

**Independent Test**: 作業フォルダのあるセッションでファイルビューアを開き、フォルダを 2 段降りてコードのファイルを開き、
色分けされた内容が読めること、画像を開いて拡大できること、戻る操作で 1 段ずつ戻れることを確かめる。

**Acceptance Scenarios**:

1. **Given** 会話を開いている, **When** 右上のピルのメニューから「ファイル」を選ぶ, **Then** そのセッションの作業フォルダのファイルとフォルダが一覧で出る（フォルダが先、名前順）
2. **Given** 一覧を表示している, **When** フォルダを押す, **Then** その中身に移り、今いる場所（パス）が示される。戻る操作で 1 段上に戻る
3. **Given** テキストのファイルを押す, **When** 開く, **Then** 等幅の文字で、種類に応じて色分けされた内容が表示される。Markdown・HTML はまずプレビューで表示され、コードのボタンで元の文字に切り替えられる
7. **Given** ファイルを開いている, **When** 検索で語を入れる, **Then** 一致した語に色が付き、件数が示され、前後の一致へ送れる
4. **Given** 画像のファイルを押す, **When** 開く, **Then** 全画面のオーバーレイで表示され、つまんで拡大できる
5. **Given** ファイルビューアを開いている, **When** 表示する場所を「エージェントのワークスペース」に切り替える, **Then** ワークスペースのファイルが同じように辿れる（ワークスペースは読むだけ）
6. **Given** 一覧の取得に失敗した, **When** 画面を見る, **Then** 失敗した理由と再試行の操作が示される

---

### User Story 2 - ファイルを直して保存する (Priority: P2)

マスターは開いたテキストのファイルをその場で直し、Gateway に保存する。保存までに他で書き換えられていれば、
上書きするか、自分の変更を捨てて読み直すかを選べる。

**Why this priority**: 小さな修正（設定の 1 行、誤字）のためだけに PC を開かずに済む。読むこと（P1）の次に価値が高い。

**Independent Test**: 作業フォルダのテキストのファイルを開いて 1 行直して保存し、Gateway 側で内容が変わったことを確かめる。
別の手段で同じファイルを書き換えてから保存し、衝突が示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 作業フォルダのテキストのファイルを開いている, **When** 編集の操作を選ぶ, **Then** 内容が編集できる状態になる
2. **Given** 編集している, **When** 保存する, **Then** Gateway 上のファイルが更新され、保存できたことが通知（Snackbar）で示される
3. **Given** 開いたあとに Gateway 側でファイルが書き換えられた, **When** 保存する, **Then** 衝突が示され、「上書きする」「変更を捨てて読み直す」から選べる
4. **Given** 保存していない変更がある, **When** 戻る操作をする, **Then** 変更を捨てるかの確認が出る
5. **Given** 保存していない変更がある, **When** アプリが終了して開き直す, **Then** 同じファイルを開くと、保存していない変更が残っている
6. **Given** 編集できないファイル（ワークスペースのファイル、大きすぎるファイル、文字ではないファイル、作業フォルダの外のファイル）を開いている, **When** 画面を見る, **Then** 編集の操作は出ず、読むだけであることが分かる

---

### User Story 3 - ファイルを端末にダウンロードする (Priority: P3)

マスターはファイルを選んで端末に保存し、ほかのアプリで開いたり共有したりする。

**Why this priority**: 成果物（画像・資料・ログ）を手元に持ち出す用途。読む・直すより頻度は低い。

**Independent Test**: 一覧からファイルを 1 つダウンロードし、端末のダウンロード先に同じ内容で保存されたこと、
保存先が示され、そこから開けることを確かめる。

**Acceptance Scenarios**:

1. **Given** ファイルを開いている、または一覧でファイルを長押ししている, **When** ダウンロードを選ぶ, **Then** 端末のダウンロード先に保存され、保存できたことと保存先が通知で示される
5. **Given** ダウンロード中, **When** 画面を消す・ファイルビューアを閉じる, **Then** ダウンロードは続き、通知とアプリ上部の帯に進み具合が出る。接続が一時的に切れても、つながり直したら続きから受け取る
6. **Given** ダウンロード中, **When** 通知か上部の帯の中止を押す, **Then** ダウンロードが止まり、途中のファイルは残らない
2. **Given** 保存できた通知が出ている, **When** 通知の「開く」を押す, **Then** 端末の対応するアプリでそのファイルが開く
3. **Given** 同じ名前のファイルがダウンロード先にある, **When** ダウンロードする, **Then** 上書きせず、別の名前で保存される
4. **Given** Gateway が内容を渡せないファイル（大きすぎる等）, **When** ダウンロードを選ぶ, **Then** できない理由が示される

---

### User Story 4 - ターミナルを操作する (Priority: P4)

マスターは Gateway のホスト上のターミナルを開き、コマンドを打って結果を見る。会話から開くと、
そのセッションの作業フォルダで始まる。アプリを離れて戻っても、同じターミナルの続きから使える。

**Why this priority**: エージェントを介さない直接操作の逃げ道。頻度は低いが、障害時の価値が高い。

**Independent Test**: 会話からターミナルを開いて `pwd` と `ls` を実行し、作業フォルダで始まっていること、
結果が表示されること、Ctrl+C・Tab・矢印が効くこと、アプリを離れて戻ると続きが出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** Gateway がターミナルの利用を許可している, **When** 右上のピルのメニューから「ターミナル」を選ぶ, **Then** そのセッションの作業フォルダでシェルにつながり、入力と出力がやり取りできる
2. **Given** ターミナルを使っている, **When** 特殊キーの行から Ctrl・Esc・Tab・矢印を押す, **Then** そのキーがシェルに送られる（Ctrl は次に打つ 1 文字と組み合わさる）
3. **Given** ターミナルを開いたままアプリを離れる, **When** 戻ってくる, **Then** 離れていたあいだの出力を含めて、同じターミナルの続きが表示される（Gateway 側で終了していない限り）
4. **Given** 画面の向きや文字の大きさが変わる, **When** 表示し直す, **Then** シェル側の行と桁の数も合わせて変わり、表示が崩れない
5. **Given** シェルが終了した（`exit` など）, **When** 画面を見る, **Then** 終了したことが示され、新しく開き直す操作が出る
6. **Given** Gateway がターミナルを許可していない（設定で無効・権限が足りない）, **When** ターミナルを開こうとする, **Then** 使えない理由が示され、開かない
7. **Given** ターミナルの出力を選ぶ, **When** コピーする, **Then** 選んだ文字がクリップボードに入る

---

### Edge Cases

- 1 つのフォルダに非常に多くのファイルがある場合: 一覧は少しずつ読み込み、スクロールがカクつかない
- 文字ではない（バイナリ）・大きすぎるファイルを開いた場合: 内容は表示せず、種類と大きさ、ダウンロードの操作だけを出す
- 文字コードが UTF-8 でないファイル: 読むだけにし、保存で内容を壊さない
- 作業フォルダの無いセッション: エージェントのワークスペースを最初に表示する
- 保存中に接続が切れた場合: 変更は残したまま、保存できなかったことと再試行を示す
- ファイルを開いているあいだにファイルが削除された場合: 保存時にそのことを示し、内容を手元に残す（ダウンロードできる）
- 編集中に画面を回転・言語を変更した場合: 変更とカーソルの位置を失わない
- ターミナルで大量の出力が流れた場合: 表示が詰まらず、操作（Ctrl+C）が効く
- ターミナルの接続が切れた場合: 再接続後に自動で続きにつなぎ直す。Gateway 側の保持時間を過ぎて消えていれば、そのことを示して開き直しを出す
- ターミナルを別の端末（PC の Control UI など）で開き直した場合: こちらは「別の場所で開かれた」ことを示し、取り戻す操作を出す
- 端末のキーボードが表示領域を狭める場合: ターミナルと特殊キーの行はキーボードの上に収まる

## Requirements *(mandatory)*

### Functional Requirements

**ファイルビューア**

- **FR-001**: アプリ MUST、会話を開いているとき、そのセッションの作業フォルダのファイルとフォルダを一覧で辿れるようにする
- **FR-002**: アプリ MUST、表示する場所を「セッションの作業フォルダ」と「エージェントのワークスペース」から切り替えられるようにする
- **FR-003**: アプリ MUST、一覧に名前・種類（フォルダ / ファイル）・大きさ・更新時刻を示し、フォルダを先に、名前順に並べる
- **FR-004**: アプリ MUST、今いる場所を示し、戻る操作（予測型「戻る」を含む）で 1 段ずつ上に戻れるようにする
- **FR-005**: アプリ MUST、テキストのファイルを等幅の文字で、種類に応じて色分けして表示する
- **FR-006**: アプリ MUST、画像のファイルを全画面のオーバーレイで、拡大できる形で表示する
- **FR-007**: アプリ MUST、文字ではない・大きすぎるファイルの内容を表示せず、種類・大きさとダウンロードの操作を示す
- **FR-008**: アプリ MUST、作業フォルダのテキストのファイルを編集して Gateway に保存できるようにする
- **FR-009**: アプリ MUST、保存時に、開いてから Gateway 側でファイルが変わっていないかを確かめ、変わっていれば衝突を示して「上書き」「読み直し」を選ばせる
- **FR-010**: アプリ MUST、保存していない変更があるまま離れるとき、捨てるかの確認を出す
- **FR-011**: アプリ MUST、保存していない変更をプロセスの終了と構成の変更を越えて残す
- **FR-012**: アプリ MUST、編集できないファイル（ワークスペースのファイル・作業フォルダの外のファイル・大きすぎる・文字ではない・UTF-8 でない）に編集の操作を出さない
- **FR-013**: アプリ MUST、ファイルを端末のダウンロード先に保存でき、保存先を示し、そこから開けるようにする
- **FR-014**: アプリ MUST、ダウンロード先に同じ名前があるとき、上書きせず別の名前で保存する
- **FR-015**: アプリ MUST、Gateway が内容を渡せないファイルのダウンロードでは、理由を示す
- **FR-016**: アプリ MUST、Markdown・HTML のファイルをふだんプレビューで表示し、コードのボタンで元の文字（等幅・色分け）に切り替えられるようにする
- **FR-017**: アプリ MUST、開いたファイルの中を検索でき、一致した語に色を付け、件数と前後の一致への送りを示す
- **FR-018**: アプリ MUST、ダウンロードを画面の消灯・ファイルビューアを閉じることを越えて続け（フォアグラウンドサービス）、進み具合と中止を通知とアプリ全体の上部の帯に示す。接続が切れたら、つながり直してからリンクを取り直し、続きから受け取る
- **FR-019a**: アプリ MUST、開いているファイルをタイトルバーの「読み直す」ボタンで読み直し、結果（「更新しました」「変更はありません」）を Snackbar で示す。編集中は出さない。ツリーは引き下げで読み直す（マスター指定 2026-11-26。ファイルビューアのタイトルバーからターミナルへの切り替えは外した）
- **FR-019b**: アプリ MUST、作業フォルダの画像（PNG・JPEG・GIF・WebP・BMP・HEIC・AVIF）で、Gateway が中身を添えず、大きさが分かって 20 MB 以内のものは、ダウンロードの短命リンクから取って表示に足りる大きさに縮めてプレビューする。リンクが無い・取れない・大きさが分からない・Gateway が大きすぎると断った画像は、種類・大きさとダウンロードを出す（FR-007）。全画面の保存は元のファイルのダウンロードにする

**ターミナル**

- **FR-020**: アプリ MUST、Gateway ホスト上の対話的なターミナルを開き、入力と出力をやり取りできるようにする
- **FR-021**: アプリ MUST、会話から開いたターミナルを、そのセッションの作業フォルダで始める
- **FR-022**: アプリ MUST、ソフトウェアキーボードに無い特殊キー（Ctrl・Esc・Tab・矢印）を送る手段を提供する
- **FR-023**: アプリ MUST、画面の大きさ・向き・文字の大きさに合わせて、シェル側の行と桁の数を合わせる
- **FR-024**: アプリ MUST、アプリを離れて戻ったとき、Gateway 側で残っている限り同じターミナルにつなぎ直し、離れていたあいだの出力を表示する
- **FR-025**: アプリ MUST、シェルの終了・接続の喪失・別の場所での開き直しを区別して示し、開き直す（取り戻す）操作を出す
- **FR-026**: アプリ MUST、Gateway がターミナルを許可していないとき、理由を示して開かない
- **FR-027**: アプリ MUST、ターミナルの出力を選んでコピーできるようにする
- **FR-029**: アプリ MUST、ターミナルの既定の背景と文字色をアプリのテーマに合わせる（ANSI の色は変えない）
- **FR-028**: アプリ MUST、会話から開いたターミナルを、この端末の接続だけのものとして開く（会話には紐付けない。エージェントからは見えない）。接続が切れたあとも Gateway が保持するあいだ（既定 5 分）は、つなぎ直して続きから使える（マスター決定 2026-11-23）

**共通**

- **FR-030**: アプリ MUST、ファイルとターミナルの操作で Gateway の権限を広げず、Gateway が拒んだ操作は理由を示して止める
- **FR-031**: アプリ MUST、ファイルビューアとターミナルを、AGENTS.md の画面遷移・ガラスの面・動きの規則に従って表示する（画面遷移は右から重なる、ガラスはタイトルバーと下部のピルだけ）

### Key Entities

- **ファイルの場所（ルート）**: セッションの作業フォルダ（読み書き）か、エージェントのワークスペース（読むだけ）。どのセッション・エージェントのものか
- **ファイルの項目**: 名前・ルートからの相対パス・種類（フォルダ / ファイル）・大きさ・更新時刻
- **開いたファイル**: 内容（文字 / 画像 / 表示できない）・開いた時点の版（衝突の確認に使う）・編集できるか・保存していない変更
- **ターミナル**: Gateway 上の識別子・始まりのフォルダ・行と桁の数・状態（つながっている / 離れている / 終了 / 別の場所で開かれた）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 会話からファイルビューアを開き、3 段下のファイルの内容を見るまでを、5 回以内の操作で行える
- **SC-002**: 500 項目のフォルダでも、一覧のスクロール中にカクつき（フレームの取りこぼし）が目で見て分からない
- **SC-003**: 1 行の修正を、ファイルを開いてから保存できたことが示されるまで 30 秒以内で終えられる
- **SC-004**: 他で書き換えられたファイルを保存しようとしたとき、10 回中 10 回、上書きの前に衝突が示される
- **SC-005**: 編集中にアプリを強制終了しても、保存していない変更は 10 回中 10 回残る
- **SC-006**: ダウンロードしたファイルは、Gateway 上の元のファイルと内容が一致する
- **SC-007**: ターミナルを開いてから入力できる状態になるまで、手元のネットワークで 3 秒以内
- **SC-008**: アプリを離れて 1 分後に戻ったとき、10 回中 10 回、同じターミナルの続きが表示される
- **SC-009**: キー入力が表示に反映されるまでの遅れが、手元のネットワークで気にならない（目安 0.2 秒以内）

## Assumptions

- 利用者はマスター 1 人で、Gateway は自分のもの。ファイルの書き込みとターミナルは、Gateway がこの端末に許可している範囲で使う（ターミナルは Gateway の管理者の権限が要る）
- ファイルの作成・削除・名前の変更・アップロードは本機能の範囲外（読む・直す・持ち出すに絞る）。作成・削除・名前の変更は spec 005（US6）で入れた
- エージェントのワークスペースは Gateway が読むだけの手段しか持たないため、読むだけとする
- 作業フォルダの外のファイルは、Gateway が許す範囲で読むだけとする
- 「大きすぎる」の線は Gateway が渡せる上限に従う（目安: 表示と編集は 1 MB 程度まで。超えるものは読むだけ・ダウンロードのみ）
- ターミナルは会話ごとに 1 つ。複数のターミナルを並べて切り替える機能は範囲外
- ターミナルは接続だけのもの（FR-028）なので、Gateway の保持時間（既定 5 分）を過ぎて離れていると消える。そのときは開き直しを出す（US4 シナリオ 3 の「Gateway 側で終了していない限り」に当たる）
- ターミナルの表示には承認済みの外部部品を使う（001 research R9、2026-11-22 承認）。コードの色分けも承認済みの部品を使う（R10）
- 入口は会話の画面の右上のピルのメニューの「ファイル」「ターミナル」（2026-11-23 変更。以前はタイトルバーのアイコン）
