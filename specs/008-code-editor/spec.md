# Feature Specification: アプリに入れるエディター（独立した編集の画面）

**Feature Branch**: `008-code-editor`（ワークツリー `openclaw/codeeditor` で進め、2026-11-28 に main にマージした）

**Created**: 2026-11-28

**Status**: Draft

**Input**: User description: "Androidってまともなビルトインのエディターがないからこのアプリにエディター含められないかな？今はファイルビュアーとかテキストプレビューに独自に組み込んでるでしょ？それで編集を押すと別Activityとして起動する感じ。スマホ編集だから高機能は求めない。行番号表示、折り返し対応、エンコードタイプ、言語識別（txt、kt、jsとかでハイライトが変わる）、テキスト編集機能、文字数カウントぐらい？Monacoだっけ？ああいうオープンソース使うほうが早い？"

## 現状（2026-11-28 時点）

- ファイルビューア（spec 002・004・005）は、読む画面の中で「編集」に切り替わる。行番号・色分け・今の行の強調・取り消し / やり直し・記号の行・下書きの保持・保存時の衝突の検出は、すでにある（spec 005 US5）
- 足りないもの: 編集中は必ず折り返す（折り返さない編集ができない）、文字コードは UTF-8 だけ（それ以外は編集できない）、文字数が分からない、言語は拡張子から決めるだけで変えられない、5,000 行を超えると編集中の色分けを止める
- 会話の添付のシート（txt・md など）と、入力欄の「コピーしたテキスト」のシートは、読むだけ
- Gateway に書き戻す手段（`sessions.files.set`・`agents.files.set`）は、中身を文字列で受け取る。Gateway のファイルには UTF-8 でしか保存できない（gateway-protocol 2026.11.6 のスキーマで確認）
- Gateway 2026.11.10 は、作業フォルダのファイルを、厳密に UTF-8 として読めて 256 KiB 以下のときだけ文字として返す。それ以外は「表示できない」扱いで、ハッシュも無い（編集できない）。書き込みも 256 KiB まで（plan research R4）

## Clarifications

### Session 2026-11-28

- Q: エディターをどこに置くか → A: 独立した Activity。ファイルビューア・文字のプレビューで「編集」を押すと、その Activity が開く（マスター指定 2026-11-28）
- Q: 機能の範囲 → A: スマホで小さく直すための最小限。行番号・折り返し・文字コード・言語の識別と色分け・編集・文字数（マスター指定 2026-11-28）
- Q: ファイルビューアの中の今の編集の切り替え → A: やめて、エディターの Activity に一本化する（同じものを直す手段を 2 つ持たない。憲章 VII）。下書き・衝突の扱いはそのまま引き継ぐ
- Q: OpenClaw のファイル以外（端末の中のファイル）も扱うか → A: 扱う。ほかのアプリの「アプリで開く」「編集」の候補にエディターを出し、元のファイルに書き戻す。アプリの中から端末のファイルを選んで開く入口は作らない（マスター回答 2026-11-28: B）
- Q: 会話の添付を直したものの保存先 → A: 端末の「ダウンロード」に保存する。エージェントへ送り返す機能は作らない（直すこと自体が少なく、返すならコピーして任意でプロンプトに入れる。マスター回答 2026-11-28: A）
- Q: 添付のシートに「編集」を置くか → A: 置かない。保存したあとの「開く」で、アプリの選択から テキストエディタ（SumahoClaw）を選べば直せる（US4 の受け口がそのまま使える。マスター指定 2026-11-28、実機で見て）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ファイルビューアから開いて直し、保存する (Priority: P1) 🎯 MVP

マスターは外出先で、作業フォルダやエージェントのファイルをファイルビューアで読んでいて、1 行直したくなる。「編集」を押すとエディターが開き、行番号と色分けのついたコードを直して保存し、戻るとファイルビューアに直した内容が出ている。

**Why this priority**: 持ち歩いているときに必要なのは「エージェントの出力を小さく直す」こと（憲章 VII の「小さく直す」）。Android には外部の定番エディターが無く、ファイルを外に出して直して戻す経路も無い。今のビューアの中の編集は、読む画面と編集の画面が同じ場所に詰め込まれていて、折り返さない編集や文字数のような編集の道具を足す余地が無い。

**Independent Test**: 300 行ほどのコード（kt）を作業フォルダで開き、「編集」→ 1 文字直す → 保存 → 戻る、で、ビューアに直した内容が出ること。Gateway 上のファイルも変わっていること。

**Acceptance Scenarios**:

1. **Given** ファイルビューアで編集できるファイル（作業フォルダ・エージェントのファイル）を読んでいる, **When** 「編集」を押す, **Then** エディターが独立した画面として開き、同じ位置（読んでいた行）から、キーボードを出さずに表示される
2. **Given** エディターを開いた, **When** 行を押す, **Then** その位置にカーソルが立ち、キーボードが出て、打った文字が入る
3. **Given** 直した, **When** 保存する, **Then** Gateway のファイルに書き込まれ、保存できたことが分かる。エディターは開いたまま
4. **Given** 保存した, **When** 戻る, **Then** ファイルビューアに戻り、保存した内容が表示されている
5. **Given** 保存していない変更がある, **When** 戻る, **Then** 「保存する / 破棄 / 続ける」を選ぶ確認が出る
6. **Given** 開いたあとにほかの端末・エージェントが同じファイルを変えた, **When** 保存する, **Then** 上書きせずに衝突を示し、「読み直して自分の変更を破棄する / それでも上書きする」から選ぶ（今のビューアと同じ）
7. **Given** 編集中にアプリが裏に回り、プロセスが終わった, **When** もう一度開く, **Then** 保存していない内容とカーソルの位置が戻っている
8. **Given** 読むだけのファイル（エージェントのワークスペース）・大きすぎるファイル・文字でないファイル, **When** ビューアで見る, **Then** 「編集」は出ない（出さない理由は今のビューアと同じ）

### User Story 2 - コードとして読める・直せる見た目 (Priority: P1)

エディターでは、左に行番号、ファイルの種類に合った色分け、今いる行の強調があり、長い行を折り返すかどうかを切り替えられる。下の帯に、今の位置（行・列）と文字数が出る。

**Why this priority**: 「42 行目を直して」のようにエージェントと行で話すには行番号が要る。コードは折り返すと構造が崩れ、文章は折り返さないと読めないので、切り替えが要る。文字数は、文章（README・告知文・プロンプト）を書くときの目安になる。

**Independent Test**: 長い行を含む kt・js・md・txt をそれぞれ開き、行番号・色分け・折り返しの切り替え・下の帯の数字が正しいことを確かめる。

**Acceptance Scenarios**:

1. **Given** エディターを開いた, **When** 見る, **Then** 左に行番号（論理行の先頭にだけ。折り返した続きの行には付けない）が出て、横にスクロールしても左に留まる
2. **Given** kt・js・py・md などのファイル, **When** 開く, **Then** 拡張子から言語を決め、その言語の色分けで表示する。txt と未知の拡張子は色分けしない
3. **Given** 言語の判定が合っていない（拡張子が無い、`.conf` の中身が YAML など）, **When** メニューから言語を選ぶ, **Then** その言語で色分けし直す。選んだ言語は、そのファイルを次に開いたときも使う
4. **Given** 折り返しがオフ, **When** 長い行を見る・直す, **Then** 行は折り返されず、横にスクロールして読める・直せる
5. **Given** 折り返しがオン, **When** 長い行を見る・直す, **Then** 画面の幅で折り返す
6. **Given** 折り返しを切り替えた, **When** 次に開く, **Then** 前回の選び方が使われる（既定: コードはオフ、md・txt などの文章はオン）
7. **Given** カーソルを動かす・文字を打つ, **When** 下の帯を見る, **Then** 今の行・列と、全体の文字数・行数が更新されている
8. **Given** 文字を選んでいる, **When** 下の帯を見る, **Then** 選んだ範囲の文字数が出る
9. **Given** 編集している, **When** 取り消し・やり直しを押す, **Then** 直前の変更が戻る・進む
10. **Given** 編集している, **When** キーボードの上の記号の行を押す, **Then** インデント（Tab）や括弧・記号が入る（今のビューアと同じ）
11. **Given** 編集している, **When** 検索を開いて語を入れる, **Then** 一致した語が強調され、前後の一致へ移れる（今のビューアと同じ）

### User Story 3 - 文字コードと改行を壊さない (Priority: P2)

マスターが開いたファイルの文字コード（UTF-8・Shift_JIS など）と改行（LF・CRLF）が下の帯に出る。化けていたら、文字コードを選び直して開き直せる。保存しても、文字コードと改行は勝手に変わらない。

**Why this priority**: 古い設定ファイルや Windows で作られたファイルを UTF-8 / LF 前提で扱うと、保存した瞬間に全行が差分になったり、日本語が化けたりする。スマホで小さく直すときに、気づかないうちにファイルを壊すのがいちばん困る。ただし Gateway 上のファイルはほぼ UTF-8 なので P2。

**Independent Test**: UTF-8（BOM あり / なし）・Shift_JIS・UTF-16 のファイルと、CRLF のファイルを開き、表示・下の帯の表示・保存後の中身（バイト）を確かめる。

**Acceptance Scenarios**:

1. **Given** ファイルを開いた, **When** 下の帯を見る, **Then** 判定した文字コード（BOM の有無を含む）と改行の種類が出る
2. **Given** 文字が化けている, **When** 下の帯の文字コードを押して別の文字コードを選ぶ, **Then** その文字コードで読み直して表示する（保存していない変更があれば、先に破棄するか確認する）
3. **Given** CRLF のファイル, **When** 直して保存する, **Then** CRLF のまま保存される（直していない行の改行も変わらない）
4. **Given** UTF-8 の BOM 付きのファイル, **When** 保存する, **Then** BOM は付いたまま
5. **Given** Gateway 上のファイル, **When** 開く, **Then** 文字コードは UTF-8（BOM の有無を含む）と示し、選び直しは出さない。UTF-8 でないファイルは Gateway が文字として渡さないので、今までどおり「編集」が出ない
6. **Given** 文字コードを判定できない（バイナリに近い）, **When** 開こうとする, **Then** エディターでは開かず、理由を示す
7. **Given** 元の文字コードで書けない文字（Shift_JIS のファイルに絵文字など）を入れた, **When** 保存する, **Then** 保存せず、その文字の位置へカーソルを移して理由を示す
8. **Given** 改行が混ざったファイル, **When** 保存する, **Then** 多い方の改行にそろえることを確認してから保存する

### User Story 4 - ほかのアプリのファイルを開いて直す (Priority: P2)

マスターは、ファイル管理アプリ・ダウンロード・ほかのアプリにある文字のファイルを「アプリで開く」で SumahoClaw のエディターに渡し、直して元のファイルに保存する。

**Why this priority**: Android に標準のテキストエディターが無いという、この機能のいちばんの動機に応える（マスター回答 2026-11-28）。OpenClaw のファイルではないので憲章 VII の外側に半歩出るが、入口はほかのアプリからの「アプリで開く」だけにし、アプリの画面には項目を増やさない（アプリの中から端末のファイルを選ぶ入口は作らない）。US1 のエディターをそのまま使い、追加は受け口と書き戻しだけなので P2。

**Independent Test**: ファイル管理アプリで txt を長押し →「アプリで開く」→ SumahoClaw を選び、直して保存し、ファイル管理アプリから開き直すと直した内容になっていること。Shift_JIS・CRLF のファイルで、直した箇所以外のバイトが変わらないこと。

**Acceptance Scenarios**:

1. **Given** ほかのアプリで文字のファイルを「アプリで開く」, **When** 候補を見る, **Then** SumahoClaw のエディターが出る
2. **Given** 書き戻しを許されたファイル, **When** 直して保存する, **Then** 元のファイルに、元の文字コード・改行で書き込まれる（UTF-8 以外の文字コードでも保存できる）
3. **Given** 読むことだけを許されたファイル, **When** 開く, **Then** 読むだけで開き、保存の代わりに「別の名前で保存」を出す
4. **Given** Gateway に接続していない, **When** ほかのアプリから開く, **Then** 接続を待たずに開ける

---

### User Story 5 - 会話の文字のプレビューから開いて直す (Priority: P3)

マスターは、エージェントが会話に添付した md・txt を、プレビューのシートで読んでいて、直して手元に残したくなる。シートで「ダウンロード」してから「開く」を押し、アプリの選択で テキストエディタ（SumahoClaw）を選んで直し、保存する（ダウンロードしたファイルに書き戻る。US4 の受け口を使い、シートに専用の「編集」は置かない）。入力欄の「コピーしたテキスト」のタイルは、シートの「編集」からエディターで直せ、保存するとタイルの中身が変わる。

**Why this priority**: 添付を直す場面は少ない（マスター回答 2026-11-28）。直した文をエージェントに返すときは、コピーしてプロンプトに入れれば足りるので、送り返す機能は作らない。入口をエディターにそろえる程度の小さな追加なので P3。

**Independent Test**: 会話の md の添付をシートで保存 →「開く」→ テキストエディタ（SumahoClaw）で直して保存し、「ダウンロード」のそのファイルが直した内容になっていること。入力欄の「コピーしたテキスト」のタイルを直し、送った .txt に直した内容が入っていること。

**Acceptance Scenarios**:

1. **Given** 会話の文字の添付（txt・md など、2 MB 以下）を保存したシート, **When** 「開く」を押してアプリの選択で テキストエディタ（SumahoClaw）を選ぶ, **Then** 保存したファイルがエディターで開く。元の添付（Gateway 側）は変わらない
2. **Given** そのエディターで直した, **When** 保存する, **Then** 「ダウンロード」の同じファイルに書き戻る（自分で保存したファイルなので、読む許可だけで渡されても書ける）
3. **Given** シート, **When** 見る, **Then** 「編集」は無い（下の行は コピー ｜ ダウンロード / 開く のまま）
4. **Given** 入力欄の「コピーしたテキスト」のタイルのシート, **When** 「編集」を押して直し、保存して戻る, **Then** タイルの中身（先頭の数行と文字数）が直した内容に変わる
5. **Given** 保存せずに戻る, **When** 変更がある, **Then** US1 と同じ確認が出る

### Edge Cases

- 大きいファイル: 2 MB を超える文字のファイルはエディターで開かない（今のビューア・添付のシートと同じ上限）。作業フォルダのファイルは Gateway の上限の 256 KiB までしか開けず（Gateway が文字として渡さない）、直して 256 KiB を超えたら保存せずに理由を示す。2 MB 以下でも行数が多い（目安 1 万行以上）ときは、入力の滑らかさを優先して、編集中だけ色分けを簡略にしてよい（憲章 I）
- 1 行がとても長い（minify された js など）: 折り返しオフでも固まらない。固まるなら、その行だけ色分けを止める
- 保存中に接続が切れた: 保存できなかったことを Snackbar で示し、再試行を出す。内容は下書きに残す
- 編集中に Gateway の接続先を切り替えた・接続情報を消した: エディターを閉じる前に、保存していない変更をどうするか確認する。前の Gateway のファイルに保存しない
- 編集中にファイルが Gateway から消えた: 保存するとき「無い」と示し、「作り直して保存 / 破棄」から選ぶ（今のビューアと同じ）
- 同じファイルを 2 つのエディターで開こうとした: 新しく開かず、開いているエディターを前に出す
- 画面の回転・折りたたみ・言語の切り替え・ダークへの切り替え: 内容・カーソル・スクロールの位置・取り消しの履歴を失わない（取り消しの履歴は、プロセスの終了を越えなくてよい）
- 文字サイズ 200%: 行番号の列と下の帯が切れたり重なったりしない。下の帯に収まらない項目は省略してよいが、文字数は残す
- 文字数の数え方: 見た目の 1 文字を 1 と数える（絵文字・結合文字も 1）。改行は数えない。行数は論理行
- 読むだけのファイルを編集で開こうとした: 「編集」を出さないので起きない。ほかの経路で来たら読むだけで開く
- 外部キーボード: 矢印・Home / End・Ctrl+Z / Ctrl+Y・Ctrl+S（保存）・Ctrl+F（検索）が効く

## Requirements *(mandatory)*

### Functional Requirements

**開く・閉じる**

- **FR-001**: アプリ MUST、エディターを、会話やファイルビューアとは別の独立した画面（独立した Activity）として開く（マスター指定）
- **FR-002**: ファイルビューアは MUST、編集できるファイルに「編集」を出し、押すとエディターを開く。ビューアの中で編集に切り替える今の作りはやめる（憲章 VII。直す手段を 1 つにする）
- **FR-003**: エディター MUST、開いたときに、呼び出し元で読んでいた位置を表示する。キーボードは、利用者が本文を押すまで出さない
- **FR-004**: エディターを閉じる（戻る）と MUST、呼び出し元の画面に戻り、保存した内容が呼び出し元に反映されている
- **FR-005**: 保存していない変更があるときに閉じようとすると MUST、「保存する / 破棄 / 続ける」を確認する
- **FR-006**: 戻る操作は MUST、予測型「戻る」で扱う（独自の戻り方を作らない）
- **FR-007**: 同じファイルをすでにエディターで開いているとき（分割画面・ほかのアプリから 2 回など）MUST、前の画面の保存していない内容を新しい画面に引き継ぎ、前の画面を閉じる（タスクをまたいで「前に出す」ことは確実にできないため。plan research R3）

**表示**

- **FR-010**: エディター MUST、左に行番号を出す。論理行の先頭にだけ付け、横スクロールしても左に留める
- **FR-011**: エディター MUST、カーソルのある論理行を背景で強調する
- **FR-012**: エディター MUST、折り返しのオン / オフを切り替えられる。オフのときは、編集中も横スクロールで読める・直せる
- **FR-013**: 折り返しの選択 MUST、ファイルの種類（コード / 文章）ごとに覚える。既定はコードがオフ、文章（md・txt・未知）がオン
- **FR-014**: エディター MUST、拡張子から言語を決めて色分けする。少なくとも、今のビューアが色分けする言語（kt・java・js・ts・py・go・rs・swift・c / cpp・cs・sh・json・xml / html・yaml・toml・css・md など）を扱う。txt と未知の拡張子は色分けしない
- **FR-015**: エディター MUST、言語を手で選び直せる（「なし」を含む）。選んだ言語はファイルごとに覚える
- **FR-016**: 色分け MUST、編集中も消さない。打った内容に追いつく（入力を止めて待たせない）

**編集**

- **FR-020**: エディター MUST、文字の入力・選択・切り取り・コピー・貼り付けを、Android の標準の操作（選択のつまみ・メニュー）で提供する
- **FR-021**: エディター MUST、取り消しとやり直しを提供する
- **FR-022**: エディター MUST、キーボードの上に、インデント（Tab）と打ちにくい記号を入れる行を出す
- **FR-023**: エディター MUST、ファイルの中を検索し、一致を強調して前後へ移れる
- **FR-024**: エディター MUST、外部キーボードの基本のショートカット（Ctrl+S 保存・Ctrl+Z / Ctrl+Y・Ctrl+F）を受け付ける

**情報の帯**

- **FR-030**: エディター MUST、画面の下に情報の帯を出す。中身: 行・列 ／ 文字数（選んでいるときは選んだ範囲の文字数）／ 行数 ／ 文字コード ／ 改行 ／ 言語
- **FR-031**: 文字数 MUST、見た目の 1 文字を 1 と数え（絵文字・結合文字を含む）、改行を数えない
- **FR-032**: 帯の文字コード・言語を押すと MUST、それを選び直すメニューを出す

**文字コードと改行**

- **FR-040**: エディター MUST、開いたファイルの文字コードを判定する。少なくとも UTF-8（BOM あり / なし）・Shift_JIS・EUC-JP・UTF-16（LE / BE）を見分ける
- **FR-041**: エディター MUST、文字コードを選び直して読み直せる。保存していない変更があれば、先に破棄するか確認する
- **FR-042**: エディター MUST、改行の種類（LF / CRLF / CR）を判定して示し、保存しても変えない。混ざっているときは「混在」と示し、保存の前に多い方にそろえることを確認する
- **FR-043**: 保存 MUST、開いたときの文字コード・BOM の有無を保つ。元の文字コードで書けない文字があれば保存せず、その位置を示す。Gateway のファイルは常に UTF-8（Gateway が UTF-8 のファイルしか文字として渡さない）なので、文字コードの選び直しを出さない
- **FR-044**: 文字コードを判定できないファイル MUST、エディターで開かず、理由を示す

**保存**

- **FR-050**: エディター MUST、保存の操作で、ファイルを開いた元（作業フォルダ・エージェントのファイル）に書き戻す。保存中は二重に保存させない
- **FR-051**: 保存 MUST、開いたあとに元が変わっていたら上書きせず、衝突を示して「読み直して変更を破棄する / それでも上書きする」から選ばせる（spec 002 FR-008・009 と同じ）
- **FR-052**: 保存の成否 MUST、Snackbar で示す。失敗したら再試行を出す
- **FR-053**: 保存していない内容とカーソルの位置 MUST、プロセスの終了と構成の変更を越えて残す（既存の下書きの仕組みを引き継ぐ）。保存したら下書きを消す

**文字のプレビューから（US5）**

- **FR-060**: 会話の文字の添付のシートに MUST NOT「編集」を置かない。直すときは、保存したファイルを「開く」から テキストエディタ（SumahoClaw）で開く（US4 の受け口。FR-070〜074）
- **FR-061**: 端末のファイルを読む許可だけで渡されたときも、エディター MUST、実際に書けるか（切り詰めずに開けるか）を確かめ、書ければ保存で元のファイルに書き戻す（自分で保存した添付など）。エージェントへ送り返す操作は作らない
- **FR-062**: 入力欄の「コピーしたテキスト」のシートは MUST、「編集」を出す。保存すると、送る前のタイルの中身を置き換える（送ったあとのものは変えない）

**ほかのアプリから（US4）**

- **FR-070**: アプリ MUST、ほかのアプリの「アプリで開く」「編集」の候補に、文字のファイル向けにエディターを出す。アプリの中に端末のファイルを選ぶ入口は作らない
- **FR-071**: 元のファイルへの書き込みを許されたときは MUST、元のファイルに、開いたときの文字コード・BOM・改行で書き戻す（UTF-8 以外もそのまま保存できる）。許されなければ読むだけで開き、「別の名前で保存」を出す
- **FR-072**: Gateway に接続していなくても MUST、開いて直して保存できる。接続の設定が無い（初回の接続前）ときも同じ
- **FR-073**: 端末のファイル MUST、開いたあとにほかのアプリが変えていたら、保存の前に衝突を示す（US1 と同じ選択肢）。変わったかを確かめられない渡し方なら、確かめずに保存する
- **FR-074**: 端末のファイルの下書き MUST、そのファイルへの読み書きの許可が続く間だけ残す。許可が切れて開き直せないときは、下書きを「別の名前で保存」できるようにする

**文言・見た目**

- **FR-080**: 利用者向けの文言 MUST、`app/src/main/res/values/strings.xml`（日本語）に置き、訳を作り直す
- **FR-081**: エディターの見た目 MUST、`AGENTS.md` と `docs/design/screens.md` に従う。決まりの無いもの（情報の帯・上部の操作）は、plan で `docs/design/screens.md` に「エディター」の節を足して決める

### Key Entities

- **編集の対象**: どこから来たか（作業フォルダ / エージェントのファイル / 会話の添付 / コピーしたテキスト / 端末のファイル）・パス or 名前・開いたときの版（衝突の判定に使う）・書き戻せるか・保存先の受け付ける文字コード（Gateway は UTF-8 だけ、端末のファイルとダウンロードは任意）
- **開いた文書**: 中身・文字コード（BOM の有無を含む）・改行の種類・言語・保存していない変更の有無・カーソル
- **エディターの好み**: 種類（コード / 文章）ごとの折り返し、ファイルごとの言語の選び直し
- **下書き**: 対象・中身・カーソル・開いたときの版（既存の下書きを引き継ぐ）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ファイルビューアで「編集」を押してから、エディターに中身が出るまで 0.5 秒以内（すでに読み込んだファイル）
- **SC-002**: 1 万行・2 MB 以下のファイルで、文字を打ってから画面に出るまで、打鍵ごとの目立った遅れが無い（実機で連打しても取りこぼさない）。スクロールがカクつかない
- **SC-003**: ファイルビューアで読んでいる状態から、1 行直して保存し、ビューアに戻るまでを、15 秒以内に終えられる
- **SC-004**: UTF-8（BOM あり / なし）・Shift_JIS・CRLF のファイルを開いて 1 文字直して保存したとき、直した箇所以外のバイトが変わらない（Gateway のファイルは UTF-8 だけが対象）
- **SC-005**: 編集中にプロセスを終わらせて開き直したとき、10 回中 10 回、保存していない内容が戻る
- **SC-006**: 文字数は、日本語・絵文字・結合文字の入った文で、人が数えた見た目の文字数と一致する

## Assumptions

- 利用者はマスター 1 人。接続先の Gateway は 1 つ
- 「エンコードタイプ」は、文字コードの表示・判定・選び直し・保存時に保つことと解釈した。改行（LF / CRLF）も同じ理由で壊さないよう含めた（表示と保持だけ。変換の操作は入れない）
- 「テキストプレビュー」は、会話の添付のシートと、入力欄の「コピーしたテキスト」のシートの 2 つと解釈した
- Gateway のファイルは UTF-8 でしか書き戻せない（`sessions.files.set`・`agents.files.set` は中身を文字列で受け取る。gateway-protocol 2026.11.6 で確認）。UTF-8 以外のファイル・256 KiB を超える作業フォルダのファイルは、Gateway 2026.11.10 が文字として返さない（plan research R4 で確認）
- 大きさの上限 2 MB は、今のビューア・添付のシート・`agents.files.set` の上限に合わせた。作業フォルダは Gateway の上限の 256 KiB
- エディターの部品を自作するか既存のオープンソース（ネイティブの Android のエディター部品など）を使うかは plan の research で決める。Monaco は公式に「モバイルのブラウザには対応しない」としており、候補から外す前提で比べる
- 端末のファイルは、ほかのアプリから渡されたものだけを扱う（Clarifications）。アプリの中で端末のファイルを選んで開く入口・最近開いたファイルの一覧は作らない
- 範囲外（入れない）: 会話の添付を直してエージェントに送り返す操作、アプリの中から端末のファイルを選んで開く入口、補完・定義へ移る・言語サーバー、置換、複数のファイルをタブで開く、差分の表示、改行・文字コードの一括変換、Markdown のプレビューとの横並び、ファイルの作成・名前の変更・削除（ツリーの操作は今のファイルビューアのまま）、2 MB を超えるファイルの編集
