# Feature Specification: エージェントの設定（概要・ファイル・スキル）

**Feature Branch**: `004-agent-settings`

**Created**: 2026-11-24

**Status**: Draft

**Input**: User description: "新しくspecを切って。エージェント設定を追加したい。チャット画面のアイコンをタップしたら出すようにして。概要、agents.md等のファイル閲覧、編集、スキルが欲しいね。あと、チャット画面のキャラクターアイコンからだと動線として分かりづらいと思う。サイドパネルに入れるか設定の中に入れるか、どこが良いかちょっと判断してみて。" / 追記: "サイドパネルのエージェント名の横にエージェント編集アイコンを追加しよう。多分それが分かりやすい。"

**関係する仕様**: ファイルを読む・直す・保存する・衝突の扱いは `specs/002-terminal-file-viewer` と同じ体験にする。食い違う場合は本仕様を正とする。

**現状（2026-11-24 時点、リポジトリと Gateway の資料で確認）**:

- アプリはエージェントの一覧（`agents.list`）と、ワークスペースを読むだけの閲覧（`agents.workspace.list` / `get`。書き込みの手段は無い）を使っている。エージェントの設定の画面は無い
- Gateway には、エージェントの起動時に読み込まれるファイル（AGENTS.md・SOUL.md・IDENTITY.md・USER.md・HEARTBEAT.md・BOOTSTRAP.md・MEMORY.md など）を一覧・読み・書きする手段がある。書き込みには、読んだ時点の内容の印（ハッシュ）を添えて衝突を検出する仕組みがある。1 ファイルあたり 2 MiB まで
- スキルは、エージェントごとの一覧（使えるか・足りない要件）、SKILL.md の読み取り、有効・無効の切り替えを Gateway が提供している。有効・無効は Gateway 全体の設定で、エージェントごとではない。SKILL.md を書き込む手段は無い
- アプリは接続時に管理者の権限（`operator.admin`）を求めており、上の操作はすべて使える
- サイドパネルの頭の看板には、エージェントの顔の画像と名前（`headlineSmall`）がある。名前の横には何も無い

## Clarifications

### Session 2026-11-24

- 入口（マスター決定）: サイドパネルのエージェントの名前の横に、編集のアイコンを置く。チャット画面のアバターからだけでは見つけにくいため
- 入口の判断（Moonshot）: サイドパネルがよい。設定の中は「アプリの設定」であり、エージェントはサイドパネルで選んでいるものなので、選んだ場所のすぐ横で直せる方が筋が通る。設定の中に置くとエージェントを選び直す手間が増え、アプリの設定とエージェントの設定が混ざる
- チャット画面のアバターを押して開く操作は、近道として残す（元の依頼）。見つけてもらう前提にはしない
- Q: 概要の項目を直せるようにするか → A: 読むだけ。名前・絵文字は IDENTITY.md を直す（FR-013）→ 2026-11-24 改訂: 名前と絵文字は agents.update で openclaw.json を直す（正攻法。Gateway が IDENTITY.md も書き直す）
- 概要は openclaw.json で定義しているエージェントのプロファイル・許可しているツールなどを、グラフィカルに表示するものにする（マスター指定 2026-11-24。FR-010 を改訂）
- 既定のモデルと思考の既定は概要から変えられる（マスター指定 2026-11-24）。モデルは agents.update の model（null で全体の既定へ）、思考は config.patch で agents.entries.<id>.thinkingDefault（baseHash 付き）。どちらも Gateway の再起動なしで反映（config.schema.lookup の reloadKind = hot）
- 概要はモデルとツールの 2 区切り（スキルは載せない）。項目は 1 行に 2 つまで並べ、モデルと思考の既定は同じ行（2026-11-24）。ファイルとワークスペースは 2 つ目のタブへ移し、タブ名を「ファイル」から「人格」に変える（人格と振る舞いを定義する項目のため。マスター指定 2026-11-24）
- 起動時に読み込まれる上限（1 ファイル約 2 万字）の警告は出さない。本家の Control UI のファイルの編集にも無い（マスター指定。FR-025 を削除）
- 設計の前提（マスター指定、憲章 VII に組み込み）: このアプリは持ち歩いて使うためのもので、Gateway の全機能を扱うコンパニオンアプリではない。本仕様も、持ち歩いているときに要るもの（指示のファイルの小さな修正、スキルが効かない理由の確認と止める・戸す）に絞り、それ以外のエージェントの設定は Web UI に任せる

### Session 2026-11-26（実装をもとに反映。コードを正とする）

- 引き継いだ値の印の文字は「全体」（「既定のモデル　既定」のように重なるため。メニューの「全体の既定を使う」とそろえる）
- 「思考の既定」は「既定のエフォート」と呼ぶ（会話のシートの「エフォート」と同じ設定のため）
- 既定のモデルは会話のピルと同じ短い名前（Opus 5.5 など）で出す。正式な名前は選択肢の下に出す
- Web 検索はエージェントごとに決められない（openclaw.json 全体の `tools.web.search`）ので、常に「全体」の印を付けて提供元の名前を出す。このエージェントが拒否の一覧に `web_search` か `group:web` を入れていれば「オフ」と出す。「（Gateway 全体）」の後ろ書きはやめる
- 値はすべて文字だけで出す（昇格した実行のオン・オフの点はやめる）
- 既定のモデル・エフォートを選んだら、値を先に出し、∨ の場所を保存中は読み込み表示、保存できたら一瞬チェックにする。保存中はその項目を押せない。失敗したら元に戻し、再試行付きで知らせる。成功の Snackbar は出さない

## User Scenarios & Testing *(mandatory)*

### User Story 1 - エージェントの指示のファイルを読んで直す (Priority: P1)

マスターはサイドパネルから選んでいるエージェントの設定を開き、AGENTS.md や SOUL.md を読む。その場で直して保存すると、次のセッションからエージェントの振る舞いに反映される。

**Why this priority**: エージェントの振る舞いを変えるいちばん直接の手段。今は PC で開くか、エージェントに頼んで書き換えてもらうしかない。

**Independent Test**: サイドパネルの編集のアイコンから設定を開き、「ファイル」で AGENTS.md を開いて 1 行足して保存する。Gateway 側でファイルが変わったこと、新しいセッションでその指示が効くことを確かめる。

**Acceptance Scenarios**:

1. **Given** サイドパネルを開いている, **When** エージェントの名前の横の編集のアイコンを押す, **Then** 選んでいるエージェントの設定の画面が右から重なって開く
2. **Given** 会話の画面, **When** 応答の横のエージェントのアバターを押す, **Then** そのエージェントの設定の画面が開く
3. **Given** 設定の画面の「ファイル」, **When** 開く, **Then** Gateway が示すファイルの一覧が、名前・役割の短い説明・大きさ・更新日時とともに出る。まだ無いファイルは「未作成」と示される
4. **Given** 一覧, **When** ファイルを押す, **Then** Markdown のプレビューで内容が出る。コードのボタンで元の文字に切り替えられ、検索もできる（002 と同じ）
5. **Given** ファイルを開いている, **When** 編集して保存する, **Then** Gateway のファイルが更新され、保存できたことが Snackbar で示される
6. **Given** 開いてから保存までに、エージェントや別の端末が同じファイルを書き換えた, **When** 保存する, **Then** 衝突が示され、「上書きする」「自分の変更を捨てて読み直す」を選べる。黙って上書きしない
7. **Given** 「未作成」のファイル, **When** 作成を選んで内容を書いて保存する, **Then** ファイルができる。保存の直前に別の誰かが作っていたら、衝突として扱う
8. **Given** 編集中に画面を閉じた・アプリが終わった, **When** もう一度開く, **Then** 下書きが残っていて、続きから直せる

---

### User Story 2 - エージェントの概要を見る (Priority: P2)

マスターは設定の画面を開いたとき、まずそのエージェントが何者かを一目で確かめる。名前・顔・使うモデル・作られた経緯・ワークスペースの様子が並ぶ。

**Why this priority**: ファイルやスキルを触る前に、どのエージェントを触っているかを取り違えないため。情報は Gateway が既に持っているので、作る量も小さい。

**Independent Test**: エージェントを 2 つ切り替えて設定の画面を開き、それぞれの名前・顔・モデルが Web UI の表示と一致することを確かめる。

**Acceptance Scenarios**:

1. **Given** 設定の画面, **When** 開く, **Then** 最初に「概要」が出る。顔の画像・名前・絵文字・既定のモデル・作られた経緯（作った人・日時。Gateway が持っている場合）が並ぶ
2. **Given** 概要, **When** 見る, **Then** ファイルの数と、スキルの数（使える数 / 全体）が示され、押すとそれぞれの切り替えに移る
3. **Given** 概要, **When** 「ワークスペースを開く」を押す, **Then** 既存のファイルビューア（002）が、このエージェントのワークスペースを表示する状態で開く

---

### User Story 3 - スキルを確かめ、有効・無効を切り替える (Priority: P2)

マスターはエージェントが使えるスキルを一覧で見て、なぜ使えないものがあるか（足りないコマンド・設定）を知り、要らないスキルを止める。

**Why this priority**: スキルが効かない理由の調べ方が、今は PC の CLI しかない。止める・戻すは日常的に要る。

**Independent Test**: 「スキル」でスキルの一覧を開き、使えないスキルの理由を読む。1 つを無効にし、Web UI でも無効になったことを確かめ、元に戻す。

**Acceptance Scenarios**:

1. **Given** 設定の画面の「スキル」, **When** 開く, **Then** スキルが一覧で出る。各行に名前・説明・状態（使用中 / 未対応 / 無効）が示される。使えないものは後ろにまとまる
2. **Given** 「要件が足りない」のスキル, **When** 押す, **Then** シートで、足りないもの（コマンド・環境変数・設定）が一覧で示される。秘密の値そのものは出ない
3. **Given** スキル, **When** 押す, **Then** SKILL.md の内容を Markdown のプレビューで読める（読むだけ）
4. **Given** スキルの行のスイッチ, **When** 切る, **Then** 状態がすぐに「無効」になり、Snackbar に「元に戻す」が出る。Gateway が拒んだら元の状態に戻り、理由が示される
5. **Given** スイッチを切る前, **When** 行を見る, **Then** 有効・無効が Gateway 全体の設定であり、ほかのエージェントにも効くことが、スキルの一覧の頭に一度だけ示されている

---

### Edge Cases

- 設定を開いたまま、サイドパネルで別のエージェントを選んだ: 開いている設定の画面は元のエージェントのまま。取り違えないよう、タイトルバーには常にエージェントの名前を出す
- 保存の途中で接続が切れた: 保存できたかどうか分からない状態として示し、再接続後に読み直して確かめる。下書きは消さない
- ファイルが 2 MiB を超える: 開くのは読むだけにして、編集できない理由を示す
- MEMORY.md・USER.md など個人の情報を含むファイル: 一覧には出すが、内容を外へ送る操作（共有）は付けない
- Gateway の版が古く、ファイルやスキルの手段が無い: その切り替えに「この Gateway では使えません」と示し、ほかの切り替えは使えるままにする
- 権限が足りず、書き込みやスキルの切り替えを Gateway が拒んだ: 理由を示して止める。アプリ側で権限を広げない
- エージェントがいない・読み込みに失敗した: 理由と再試行を示す
- スキルの数が多い（100 件以上）: 一覧の上部に絞り込みの検索を出す

## Requirements *(mandatory)*

### Functional Requirements

**入口**

- **FR-001**: サイドパネル MUST、エージェントの名前の横に編集のアイコン（Hugeicons の edit）を置き、押すと選んでいるエージェントの設定の画面を開く。アイコンには `contentDescription` を付け、押せる領域は 48dp 以上にする
- **FR-002**: 会話の画面 MUST、応答の横のエージェントのアバターを押すと、そのエージェントの設定の画面を開く。TalkBack から呼べるよう操作のラベルを付ける
- **FR-003**: 設定の画面 MUST、新しい画面として右から重なって開く（中身の多い詳細のため。AGENTS.md 2.7 の自動化の詳細と同じ扱い）。タイトルバーにはエージェントの名前を出す
- **FR-004**: 設定の画面 MUST、「概要」「ファイル」「スキル」を、画面下部に浮くガラスのピル型のタブで切り替える。開いたときは「概要」。切り替えた位置と各タブの読んでいた位置は、構成の変更とプロセスの終了を越えて残す

**概要**

- **FR-010**: 概要 MUST、openclaw.json のエージェントの定義を、見て分かる形で表示する（読むだけ）。項目: 顔・名前・絵文字・作られた経緯、既定のモデル（短い名前）、既定のエフォート（段階のメーター）、ツールのプロファイル（4 つのうち選ばれているものを塗る）、追加で許可・拒否（チップ。拒否はエラーの色）、コマンドの実行のモード、ファイルの読み書きの範囲、昇格した実行、Web 検索（全体の設定。このエージェントが拒否していればオフ）、ワークスペースの名前。エージェントの定義に無く既定（`agents.defaults`・`tools`）から引き継いだ値には「全体」の印を付ける（2026-11-26 に「既定」から改称）。既定のモデルと既定のエフォートだけは概要から選んで変えられ（Clarifications 2026-11-24）、それ以外の変更は Web UI で行う（憲章 VII。マスター指定 2026-11-24）
- **FR-011**: 概要 MUST、ファイルの数とスキルの数（使える数 / 全体）を表示し、押すとそのタブに移る
- **FR-012**: 概要 MUST、このエージェントのワークスペースを既存のファイルビューア（002）で開く操作を持つ
- **FR-013**: 概要 MUST、名前と絵文字を変える操作を持つ（Gateway の `agents.update`。openclaw.json の name・identity を書き換え、IDENTITY.md も Gateway が書き直す。Control UI の「アイデンティティ」と同じ）。Gateway に手段が無ければ操作を出さない。既定のモデル・エフォートは概要の項目から選ぶ（FR-010）。セッションごとのモデルは会話の中で切り替える（2026-11-24 改訂。以前は「読むだけ・IDENTITY.md を直す」）

**ファイル**

- **FR-020**: ファイル MUST、Gateway が示すエージェントのファイルの一覧を、名前・役割の短い説明・大きさ・更新日時・未作成かどうかとともに表示する。役割の説明はアプリが持つ（AGENTS.md = 振る舞いの指示、SOUL.md = 人格と口調、IDENTITY.md = 名前と雰囲気、USER.md = 利用者について、HEARTBEAT.md = 定期の見回り、MEMORY.md = 長く覚えておくこと、BOOTSTRAP.md = 初回の儀式。知らない名前は説明なし）
- **FR-021**: ファイルを開く・読む・検索・プレビューとコードの切り替え・編集・下書きの保持 MUST、002 のファイルビューアと同じ体験にする（同じ部品を使う）
- **FR-022**: 保存 MUST、読んだ時点の内容の印を添えて行い、他で変わっていれば衝突として示す。「上書きする」「自分の変更を捨てて読み直す」を選べるようにする。未作成のファイルを作るときは、その間に作られていないことを条件にする
- **FR-023**: 保存できたこと・失敗したことを Snackbar で示す。失敗は理由と再試行を付ける
- **FR-024**: 2 MiB を超えるファイル MUST、読むだけで開き、編集できない理由を示す
- **FR-025**: （削除 2026-11-24）起動時に読み込まれる上限の警告は出さない。本家の Control UI も出していない（マスター指定）
- **FR-026**: 保存の前に、内容を変えずに閉じようとしたときは何も聞かない。変えたまま閉じたときは下書きとして残す（002 と同じ）

**スキル**

- **FR-030**: スキル MUST、そのエージェントから見えるスキルの一覧を、名前・説明・状態（使用中 / 未対応 / 無効）とともに表示する。並び順は、使える → 要件が足りない → 無効、その中は名前順
- **FR-031**: 要件が足りないスキル MUST、足りないもの（コマンド・環境変数・設定）を、共通のボトムシートで示す。秘密の値は表示しない
- **FR-032**: スキル MUST、SKILL.md を Markdown のプレビューで読めるようにする（読むだけ。Gateway に書き込みの手段が無いため）
- **FR-033**: スキルの有効・無効 MUST、行のスイッチで切り替える。状態を先に変えて見せ、Gateway が拒んだら戻して理由を示す。切り替えたあとは Snackbar で「元に戻す」を出す（元に戻せる操作なので確認のダイアログは出さない）
- **FR-034**: スキルの一覧の頭 MUST、有効・無効が Gateway 全体の設定で、ほかのエージェントにも効くことを一度だけ示す
- **FR-035**: スキルが 20 件を超えるとき MUST、一覧の上に名前と説明での絞り込みを出す
- **FR-036**: スキルの追加（ClawHub からの導入・アップロード）と削除は今回の範囲外

**共通**

- **FR-040**: 取得中は中身の形のプレースホルダーを出し、そろったらフェードで入れ替える（AGENTS.md 2.8）
- **FR-041**: Gateway に手段が無い・権限が無いときは、そのタブに理由を示し、ほかのタブは使えるままにする
- **FR-042**: 見た目と動きは AGENTS.md に従う（一覧はカードにしないシンプルなリスト、ガラスはタイトルバーと下部のピルだけ、文言は `strings.xml` の日本語、アイコンは Hugeicons）

### Key Entities

- **エージェント**: ID・名前・絵文字・顔の画像・既定のモデル・作られた経緯。Gateway の一覧から取る
- **エージェントのファイル**: 名前・役割・大きさ・更新日時・未作成かどうか・内容・内容の印（衝突の検出用）・下書き
- **スキル**: 名前・説明・状態・足りない要件・SKILL.md の内容・有効かどうか（Gateway 全体）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて使う人の 9 割以上が、説明なしでサイドパネルからエージェントの設定を 10 秒以内に開ける
- **SC-002**: サイドパネルを開いてから AGENTS.md の 1 行を直して保存するまで、30 秒以内にできる
- **SC-003**: 他で書き換えられたファイルを保存しようとしたとき、100% 衝突として示され、黙って上書きされない
- **SC-004**: 画面を閉じる・アプリを強制終了しても、編集中の内容の 100% が下書きとして戻る
- **SC-005**: 使えないスキルについて、理由が分かるまでの操作が 1 回（行を押す）で済む
- **SC-006**: スキルの切り替えが、押してから見た目に反映されるまで待たされない（通信の結果を待たずに反映される）

## Assumptions

- 対象は、サイドパネルで選べる種類のエージェント（system のものは除く）
- ファイルの一覧に出す範囲は Gateway が決める（起動時に読み込まれるファイル）。ワークスペースのそのほかのファイルは、既存のファイルビューアで読む（書き込みは Gateway に手段が無い）
- SKILL.md の編集・スキルの作成（Skill Workshop）は、Gateway に書き込みの手段がそろうまで範囲外
- エージェントの作成・削除・ワークスペースの付け替えは範囲外（Web UI で行う）
