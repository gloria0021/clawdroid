## Clarifications

### Session 2026-11-23（実装中にマスターが決めたことを反映）

- サイドパネルの頭: 選んでいるエージェントの顔の画像を、ステータスバーの裏まで横いっぱいに敷き、下へいくほど背景に溶かす。右上に閉じる。画像の下にエージェントの名前を大きく出す
- サイドパネルの操作は 1 行: 左にホーム・自動化（文字付き）、右に新しいセッション・設定（アイコンだけ）。設定はこの行から開く
- ホーム（エージェントの main のセッション）とピン留めしたセッションを、履歴より上に置く。ピン留めしたものは履歴の一覧に重ねて出さない
- 履歴は「更新順 / 作業フォルダ別」を切り替えられる（エージェントごとに保持）。フォルダ別はフォルダを親にしたツリーで、開閉できる
- サイドパネルに出すエージェントは最大 4 体。並びと表示する・しないは設定で決める。エージェントの切り替えはタブを押すだけ（横のスワイプは閉じる操作）
- 会話の画面は帯（TopAppBar）を置かない。右上に「Clawdroid」のガラスのピルだけを浮かせ、押すとセッションのメニュー（名前を変更・ピン留め、区切って ファイル・ターミナル・並行開発を開始・変更量）。サイドパネルは左端からのスワイプで開く。ヘッダに作業フォルダ名は出さない
- 並行開発（Git のワークツリー）でセッションを分けられる。元にするブランチは一覧から選び、今のブランチを初期値にする
- 「別のフォルダで続ける」（会話を引き継いで作業フォルダを変える）は廃止
- テーマ「モダン」の名前は「Monochrome」。カスタムの色は RGB のスライダーとカラーコードで選ぶ
- 透過効果の強さ（ガラスの屈折・ぼかしの強さ）は設定で 0〜10 の 10 段階に変えられる（不透明度は固定のまま。AGENTS.md 2.10）
- 表示のフォント（LINE Seed JP / システム）と文字の大きさを設定で選べる
- 応答の下の操作は 日時・返信（引用して入力欄へ）・コピー。共有は置かない
- Gateway の再起動のボタンは設定にだけ置く

### Session 2026-11-26（実装をもとに反映。コードを正とする）

- サイドパネルは会話の上に重ねず、`DismissibleNavigationDrawer` で会話を右へ押し出して出す。パネル自体は横に動かさず会話の下に置いたままにし、引き出すにつれて看板も含めた中身が少し下から浮き上がり、背景色のもやが晴れる。パネルの面は会話より一段沈める（`surfaceContainerLow`）。入口のアイコン（ハンバーガー・エージェントの顔）は置かない
- 初回だけ、パネルを 1/3 まで引き出して止め、会話側を `scrim` で沈めて「サイドパネルでエージェントを管理します」と「了解」を出す。「了解」・戻る・自分で引き出すまでパネルは閉じない。デバッグ版は会話のメニューの「デバッグ → サイドパネルヒント」で再生できる
- 入力欄の下の行は 添付 ｜ 実行権限（今の段階のアイコン）｜ モデルのピル ｜ 音声 ｜ 送信（入力が空で実行中なら停止）。モデルのピルは中身の長さで、文字はアプリの文字サイズに連動させない。添付・実行権限・モデルを押したら入力欄のフォーカスを外し、閉じてもキーボードを戻さない。送信したらキーボードを閉じる
- 入力欄のプレースホルダーは、ウィットのある候補からランダムに 1 つ（空に戻るたびに選び直す）。入力した文字と見分けられるよう薄く出す
- セッションのシートは「モデル」（モデル・エフォート・コンテキストウィンドウの帯と内訳）→ プロバイダの使用量 → リソース（ホストのメモリ・ディスク）。実行権限はシートから入力欄に移す。選択のポップアップは押したボタンの位置から広がる
- 設定を変えたら値を先に出し、その場所の印を保存中は読み込み表示、保存できたら一瞬チェックにする。失敗したら元に戻し、再試行付きで知らせる（会話のモデル・エフォート・実行権限、エージェントの既定のモデル・エフォート）
- 生成中の応答の文字は 1 文字ずつフェードで出す（開いた時点で届いていた分は動かさない）。推論中の状態の言い回しは 1 段大きい文字
- 吹き出しの文字を選んだ「プロンプトに入力」は、本文に混ぜず引用のタイルにする。100 文字以上で改行を含む貼り付けは、コピーしたテキストのタイルにする（FR-039）
- 会話のメニューはピルの右端にそろえて開く。変更量は 2 行（追加・削除）で 4 桁の幅に固定する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Gateway に接続してエージェントのセッションと会話する (Priority: P1)

マスターはスマホでアプリを開き、自分の OpenClaw Gateway に接続する。左端からスワイプしてサイドパネルを開くと画面いっぱいに広がり、
頭に選択中のエージェントの顔と名前、その下にホーム・自動化・設定の行、ピン留めしたセッション、「セッション」の見出し（並べ方の切り替え: 更新順 / 開発）、そのすぐ下に「+ 新規セッション」の行、アクティブなセッションの一覧が並ぶ。アーカイブ済みは一覧の末尾に閉じた状態で置き、押すと開く（2026-11-24 マスター指定）。
下部にはエージェントのピル型タブ（例: Moonshot、Wordsmith）が浮かび、ホーム・自動化・履歴は選択中のエージェントのものを示す。セッションを選ぶと会話が表示され、メッセージを送るとエージェントの応答が
流れるように届く。別のエージェントのタブに切り替えると、セッション一覧もそのエージェントのものに
切り替わる。

**Why this priority**: チャットはアプリの存在理由そのもの。接続・エージェント切り替え・会話だけで、
外出先から OpenClaw を使うという主目的を満たせる。

**Independent Test**: 接続情報を入れて起動し、エージェントを切り替え、既存のセッションを開いて
メッセージを送り、応答を最後まで受け取れれば単独で価値を確かめられる。

**Acceptance Scenarios**:

1. **Given** 未接続の初回起動, **When** アプリを開く, **Then** Gateway の接続先とゲートウェイトークンを求める画面が表示される
2. **Given** 接続画面, **When** 接続先とゲートウェイトークンを入力して接続する, **Then** 接続に成功し、既定のエージェントのセッション一覧が表示される。次回以降の起動ではこの画面を出さない
3. **Given** 接続画面, **When** 誤ったトークンや到達できない接続先で接続する, **Then** 入力内容を残したまま、原因（認証の拒否・到達できない・端末の承認待ち）を区別して示す
4. **Given** エージェント A のセッション一覧を表示中, **When** サイドバーでエージェント B のタブを選ぶ, **Then** タブの選択面がばねで B へ移動し、頭の顔と名前・ホーム・自動化・履歴が B のものにフェードで入れ替わる。入れ替えの途中でもタブを再度押せる
5. **Given** セッションを開いている, **When** メッセージを送る, **Then** 自分のメッセージが即座に会話に加わり、エージェントの応答が届いた分から順に表示される
6. **Given** 応答が生成中, **When** 停止を押す, **Then** 生成が止まり、それまでの応答が残る
7. **Given** 応答にツールの実行が含まれる, **When** 会話を読む, **Then** ツールの実行は折りたたまれた行として表示され、展開して内容を見られる
8. **Given** 長い会話を上へスクロールしている, **When** 新しい応答が届く, **Then** 読んでいる位置は動かず、最下部へ戻るボタンが現れる
9. **Given** 入力欄, **When** マイクを押して話す, **Then** 端末の音声認識で文字になった内容が入力欄に入り、送信前に直せる
10. **Given** 応答が生成中, **When** 続けてメッセージを送る, **Then** 生成中の実行に差し込まれ（steer）、取り込まれるまでは入力欄の上に待ちの行として出る。待ちの行は取り消すか、入力欄に戻して直せる
11. **Given** エージェントが質問してきた（`ask_user`）, **When** 質問のシートを開く, **Then** 1 問ずつ選択肢から答えられ、「その他」を選んだときだけ自由に書ける。シートを閉じると「あとで」になり、入力欄の上から開き直せる

### User Story 2 - エージェントごとにチャットの内容を通知で受け取る (Priority: P2)

マスターがアプリを閉じていても、エージェントから応答が届くと通知が出る。通知にはエージェント名・
セッション名・応答の内容が表示され、エージェントごとにまとまる。通知を開くとそのセッションが開き、
通知から直接返信もできる。エージェントごとに通知のオン・オフや音を変えられる。

**Why this priority**: マスターが「必須」と指定した機能。エージェントに依頼して画面を離れ、終わったら
知らせを受けて戻る、という使い方の要になる。

**Independent Test**: アプリを閉じた状態で別の端末からエージェントに依頼し、応答の内容を含む通知が
エージェントごとにまとまって届くこと、通知から返信できることを確かめる。

**Acceptance Scenarios**:

1. **Given** アプリがバックグラウンドまたは閉じている, **When** エージェントの応答が完了する, **Then** エージェント名・セッション名・応答の内容（長ければ冒頭）を含む通知が出る
2. **Given** 複数のエージェントから応答が届いた, **When** 通知を見る, **Then** 通知はエージェントごとにまとまり、それぞれ別に開ける
3. **Given** 通知が出ている, **When** 通知を開く, **Then** そのセッションの該当する応答の位置が開く
4. **Given** 通知が出ている, **When** 通知の返信欄から送る, **Then** アプリを開かずにそのセッションへ送られ、送れたかどうかが通知に示される
5. **Given** 通知の設定, **When** エージェント B の通知をオフにする, **Then** B の応答では通知が出ず、他のエージェントの通知は出続ける
6. **Given** マスターがそのセッションを画面で開いている, **When** 応答が届く, **Then** 通知は出さない
7. **Given** Gateway が承認を求めた, **When** アプリを開いていない, **Then** 承認待ちを知らせる通知が出て、開くと承認の操作に進める
8. **Given** 自動化（cron）の実行が失敗した, **When** アプリを開いていない, **Then** 失敗を知らせる通知が出る

### User Story 3 - 作業フォルダを指定して新しいセッションを作る (Priority: P3)

マスターはサイドパネルの新しいセッションのボタンから新しいセッションを始める。その際、エージェントが作業する
フォルダを、直近に使った 5 つのフォルダか、Gateway のホスト上を辿って選べる。指定しなければエージェントの既定の作業フォルダになる。
作ったセッションはサイドバーの一覧の先頭に現れ、作業フォルダ別の表示ではそのフォルダの下に並ぶ。
進行中のセッションからは、Git のワークツリーで作業を分けた別のセッション（並行開発）も始められる。

**Why this priority**: 開発の依頼ではフォルダの指定が欠かせない。会話（P1）に次いで使用頻度が高い。

**Independent Test**: フォルダを選んでセッションを作り、作業フォルダ別の一覧でそのフォルダの下に並ぶことと、エージェントが
そのフォルダで作業することを確かめる。

**Acceptance Scenarios**:

1. **Given** 任意の画面, **When** 新規チャットを押す, **Then** 空の会話が開き、入力欄にフォーカスが移る
2. **Given** 新規セッションの作成中, **When** 空の会話のフォルダのチップからフォルダ選択を開き、直近のフォルダか、ホスト上を辿ったフォルダを選ぶ, **Then** チップがそのフォルダ名になり、最初のメッセージでそのフォルダを作業場所とするセッションが作られる
3. **Given** フォルダを選ばずに最初のメッセージを送る, **When** セッションが作られる, **Then** エージェントの既定の作業フォルダが使われる
4. **Given** セッションを作った, **When** サイドバーを開く, **Then** 新しいセッションが一覧の先頭に、位置の移動を伴って現れる
5. **Given** Git の作業フォルダのセッションを開いている, **When** メニューの「並行開発を開始」から、ブランチ名（空なら会話のタイトルから自動）・元にするブランチ（一覧から選ぶ。初期値は今のブランチ）・会話を引き継ぐかを決めて作る, **Then** 新しいワークツリーで作業する別のセッションが作られて開く
6. **Given** 並行開発のシートで、既にあるブランチと同じ名前を入れた, **When** 作ろうとする, **Then** 作る前に重なりを示し、作成を押せない

### User Story 4 - モデル・エフォート・使用量を確かめて切り替える (Priority: P4)

マスターは入力欄のモデルのピル（使ったコンテキストの分だけ塗りが伸びる）でモデルを確かめ、押して開くセッションのシートで
モデル・エフォート（思考の深さ）を切り替える。権限は入力欄の実行権限のボタンで切り替える（2026-11-26）。同じシートで、そのセッションの
コンテキストウィンドウの使用量と内訳、プロバイダの使用量（5時間枠・週枠などの割合と、枠が戻る時刻）、Gateway のホストのメモリ・ディスクが見える。

**Why this priority**: 長時間の作業ではコンテキストと使用枠の残りが判断材料になる。会話と作成の次に必要。

**Independent Test**: セッションを開き、モデルとエフォートを切り替えて次の応答に反映されること、
使用量の表示が Web UI の値と一致することを確かめる。

**Acceptance Scenarios**:

1. **Given** セッションを開いている, **When** モデルの選択を開く, **Then** Gateway が公開しているモデルの一覧が表示され、選んだモデルがそのセッションに適用される
2. **Given** 選択中のモデルがエフォートの選択肢を公開している, **When** エフォートを選ぶ, **Then** 次の実行からそのエフォートが使われる
3. **Given** 選択中のモデルがエフォートの選択肢を持たない, **When** 入力欄を見る, **Then** エフォートの選択は表示されない（推測の選択肢を出さない）
4. **Given** セッションを開いている, **When** 詳細シートを開く, **Then** コンテキストの使用量・プロバイダの使用枠・ホストのメモリとディスクが表示される
5. **Given** プロバイダの使用量が取得できない, **When** 詳細シートを開く, **Then** その欄だけが取得できない状態を示し、他の表示は妨げない

### User Story 5 - ファイルを見て、直して、保存する (Priority: P5)

マスターはセッションの作業フォルダ（またはエージェントのワークスペース）のファイルを一覧で辿り、
開いて読む。コードは等幅・色分けで表示され、その場で編集して Gateway に保存できる。
必要なファイルは端末にダウンロードできる。

**Why this priority**: エージェントの成果物をスマホで確かめ、小さく直す用途。チャットだけでも
内容は伝わるため、P1〜P3 より後でよい。

**Independent Test**: 作業フォルダのファイルを開き、1 行直して保存し、Gateway 側で内容が
変わったこと、別のファイルを端末にダウンロードできることを確かめる。

**Acceptance Scenarios**:

1. **Given** セッションを開いている, **When** ファイルビューアを開く, **Then** 作業フォルダのファイルとフォルダが一覧で表示され、辿れる
2. **Given** テキストファイルを開いている, **When** 編集して保存する, **Then** Gateway 上のファイルが更新され、保存できたことが Snackbar で示される
3. **Given** 編集中に保存せず閉じようとする, **When** 戻る操作をする, **Then** 破棄するかの確認が出る。アプリが終了しても下書きは残る
4. **Given** ファイルを選んでいる, **When** ダウンロードを選ぶ, **Then** 端末のダウンロード先に保存され、保存先が示される
5. **Given** 画像ファイルを開く, **When** タップする, **Then** 全画面のオーバーレイで拡大して見られる

### User Story 6 - ターミナルを操作する (Priority: P6)

マスターは Gateway のホスト上のターミナルを開き、コマンドを打って結果を見る。作業フォルダの
ある セッションから開くと、そのフォルダで始まる。

**Why this priority**: エージェントを介さない直接操作の逃げ道。頻度は低いが、障害時に価値が高い。

**Independent Test**: ターミナルを開いて `pwd` と `ls` を実行し、結果が表示されること、
Ctrl・Tab・矢印など特殊キーが送れることを確かめる。

**Acceptance Scenarios**:

1. **Given** Gateway がターミナルの利用を許可している, **When** ターミナルを開く, **Then** シェルにつながり、入力と出力がやり取りできる
2. **Given** ターミナルを使用中, **When** 特殊キーの行から Ctrl・Esc・Tab・矢印を押す, **Then** そのキーがシェルに送られる
3. **Given** ターミナルを開いたままアプリを離れる, **When** 戻ってくる, **Then** 同じターミナルの続きが表示される（Gateway 側で終了していない限り）
4. **Given** Gateway がターミナルの利用を許可していない, **When** ターミナルを開こうとする, **Then** 使えない理由が表示される

---

### User Story 7 - ワンボタンで Gateway を再起動する (Priority: P7)

Gateway の調子が悪いとき、マスターはボタン 1 つで再起動を指示する。確認ダイアログを経て
再起動が始まり、アプリは切断から再接続までの状態を示し、戻ったら会話を続けられる。

**Why this priority**: 頻度は低いが、外出先で PC に触れずに復旧できることの価値が大きい。

**Independent Test**: 再起動ボタンを押して確認し、切断→再接続の表示を経て、セッションが
再び操作できることを確かめる。

**Acceptance Scenarios**:

1. **Given** 接続中, **When** 再起動ボタンを押す, **Then** 実行中の作業への影響を説明する確認ダイアログが出る
2. **Given** 確認ダイアログ, **When** 再起動を選ぶ, **Then** Gateway に再起動が指示され、アプリは再起動中→再接続中→接続済みの状態を順に示す
3. **Given** 再起動後に再接続した, **When** 開いていたセッションに戻る, **Then** 会話と読んでいた位置がそのまま残っている
4. **Given** 一定時間内に再接続できない, **When** 待ち続ける, **Then** 失敗を Snackbar で示し、再試行の操作を出す

### User Story 8 - 自動化（cron）を管理する (Priority: P8)

マスターは Gateway に登録された自動化（定期実行・一度きりの予約など）を一覧で確かめ、作成・編集・
有効と無効の切り替え・今すぐ実行・削除ができる。各自動化の最近の実行結果を見て、実行で生まれた
会話を開ける。

**Why this priority**: 定期レポートなどの自動化を外出先から見直し・止められる価値は大きいが、
会話と通知が先に要る。

**Independent Test**: 自動化を 1 件作って今すぐ実行し、実行結果と実行で生まれた会話を開けること、
無効にすると次の予定が止まること、削除できることを確かめる。

**Acceptance Scenarios**:

1. **Given** 自動化の画面, **When** 開く, **Then** エージェントごとの自動化が、名前・スケジュール・有効か無効か・次の実行時刻・前回の結果とともに一覧で表示される
2. **Given** 自動化の画面, **When** 新規作成で名前・対象のエージェント・スケジュール（日時指定 / 一定間隔 / cron 式）・依頼内容を入力して保存する, **Then** Gateway に自動化が登録され、一覧に加わる
3. **Given** 既存の自動化, **When** 編集して保存する, **Then** 変更が Gateway に反映される
4. **Given** 有効な自動化, **When** スイッチで無効にする, **Then** 次の実行が止まる。有効に戻すと再開する
5. **Given** 自動化, **When** 今すぐ実行を押す, **Then** 実行が始まり、完了すると結果が一覧に反映される
6. **Given** 自動化, **When** 削除を選ぶ, **Then** 確認ダイアログを経て削除される
7. **Given** 自動化の詳細, **When** 実行履歴を開く, **Then** 各回の結果（成功・失敗・所要時間）が表示され、実行で生まれた会話を開ける
8. **Given** cron 式を入力中, **When** 式が正しくない, **Then** 保存前に誤りを示し、正しければ次の実行予定を示す

### User Story 9 - テーマを選ぶ (Priority: P9)

マスターは設定で外観（システム / ライト / ダーク）と、テーマ（OpenClaw・Monochrome・ダイナミック・
カスタム）、浮いている面の透かし方（ガラス / ぼかし）とその強さ、表示のフォントと文字の大きさを選ぶ。変更は即座に全画面へ反映される。
仕組みは Gerbil（マスターの別アプリ）のテーマ機能を参考にする。

- **OpenClaw**: OpenClaw の赤いテーマカラーを象徴する配色。初期のテーマ
- **Monochrome**（旧称モダン）: モノクロを基調にした配色
- **ダイナミック**: 端末の壁紙から取った色の配色
- **カスタム**: マスターが自由に決めた色（RGB のスライダーとカラーコード）から作る配色

**Why this priority**: 体験の質を上げるが、無くても主機能は使える。

**Independent Test**: 設定で各項目を切り替え、即座に反映されることと、アプリを再起動しても
保持されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 設定画面, **When** 外観をダークにする, **Then** 全画面がダークの配色に切り替わる（純黒は使わない）
2. **Given** 初回起動, **When** 画面を見る, **Then** OpenClaw テーマ（赤を基調）で表示される
3. **Given** 設定画面, **When** Monochrome を選ぶ, **Then** 色味のないモノクロの配色に切り替わり、リンクや強調も判別できる
4. **Given** 設定画面, **When** ダイナミックを選ぶ, **Then** 壁紙の色から取った配色に切り替わる
5. **Given** 設定画面, **When** カスタムを選び色を指定する, **Then** その色から生成した配色が全画面に適用される。白や灰色のような無彩色を指定しても、勝手に色が付かない
6. **Given** 設定画面, **When** 透かし方を「ぼかし」にする, **Then** 浮いている面がすべてぼかしの表現に切り替わる。強さのスライダーで、ガラスの屈折・ぼかしの強さを変えられる
7. **Given** テーマを変更した, **When** アプリを終了して再度開く, **Then** 選んだテーマが保持されている

### Edge Cases

- 接続が途中で切れた場合: 表示済みの会話は残し、上部に再接続中であることを控えめに示す。送信中のメッセージは失われず、再接続後に送るか、失敗として再試行を出す
- Gateway の認証が失効・拒否された場合: 接続設定へ誘導し、理由を示す
- エージェントにセッションが 1 件も無い場合: 空の状態の説明と新規チャットの導線を出す
- 非常に長い会話（数千メッセージ）や巨大なツール出力: スクロールがカクつかないよう、古い部分は必要になってから読み込み、巨大な出力は折りたたんで先頭だけを出す
- 応答の生成中にエージェントを切り替えた場合: 生成は Gateway 側で続き、戻ると続きが表示される
- アーカイブ済みのセッションを開いた場合: 入力欄を無効にし、アーカイブ解除の操作を出す
- バイナリ・巨大ファイルを開こうとした場合: 編集はできず、ダウンロードだけを出す
- 編集中のファイルが Gateway 側で別途変更された場合: 保存時に衝突を示し、上書きか破棄かを選ばせる
- 再起動の指示中に同じボタンを連打した場合: 指示は 1 回だけ送られる
- 端末の省電力設定や電池の最適化で、常駐が止められた場合: 通知が届かない可能性があることを設定画面で示し、最適化の対象から外す導線を出す
- 常駐中に接続が切れた場合: 自動で再接続し、切れていたあいだに完了した応答は再接続後にまとめて通知する
- 通知の許可が無い場合: 通知の設定画面で許可を求め、拒否されていれば理由と端末設定への導線を出す
- 短時間に大量の応答が届いた場合: 同じセッションの通知は 1 つにまとめて更新し、通知が並び続けない
- 自動化の実行中に削除・編集した場合: 実行中の回は Gateway の扱いに従い、結果を一覧に示す
- タブレット・折りたたみ端末: サイドバーとチャットを 2 ペインで並べて表示する
- 文字サイズ 200%: タブ・入力欄・使用量表示が切れたり重ならない

## Requirements *(mandatory)*

### Functional Requirements

**接続**

- **FR-001**: 未接続のとき、アプリ MUST、Gateway の接続先とゲートウェイトークンを求める接続画面を表示し、入力された値で接続する
- **FR-004**: 接続に失敗したとき、アプリ MUST、認証の拒否・到達できない・端末の承認待ちを区別して示す。承認待ちは実行するコマンド（コピー可）と手順の進み具合を、つまずいたときは理由ごとの次の一手（入れ直す・再試行・Tailscale を開く・更新）と、コピーできる詳細を示す。初めての接続で承認を経たときは「接続しました」を見せてから会話へ進む（本家の Android アプリに倣う。2026-11-24 マスター指定）
- **FR-005**: アプリ MUST、設定から接続先とトークンを変更・削除（切断）できるようにする
- **FR-002**: アプリ MUST、認証情報を端末内の保護された領域に保存し、画面・ログに平文で出さない
- **FR-003**: アプリ MUST、接続状態（接続済み・再接続中・切断）を常に把握し、切断時は自動で再接続を試みる

**ナビゲーションとエージェント**

- **FR-010**: アプリ MUST、左端からのスワイプで開き、全画面まで広がるサイドパネル（Gemini 型）を持つ。上から 頭の看板（選択中のエージェントの顔の画像を横いっぱいに敷いて下へ溶かし、右上に閉じる）・エージェントの名前・操作の行（左にホーム・自動化を文字付きで、右に設定をアイコンだけで）・ピン留めしたセッション・「セッション」の見出しの行（並べ方の切り替え）・「+ 新規セッション」の行・アクティブなセッションの一覧（見出しなし）・アーカイブ済み（ふだん閉じた見出し。押すと開く）を並べ、下部にはエージェントの数だけピル型のタブを浮かべる。エージェントが 1 体ならタブは出さない。パネルは会話の下に置いたまま、会話を右へ押し出して見せる（2026-11-26。引き出しの奥行きと初回の案内は Clarifications の Session 2026-11-26）
- **FR-011**: エージェントのタブを切り替えると、アプリ MUST、サイドバーのセッション一覧をそのエージェントのものへ同時に切り替える
- **FR-012**: アプリ MUST、セッション一覧に各セッションのタイトル（1 行）・最終更新・未読の目印・実行中の目印を 1 行で表示する
- **FR-013**: アプリ MUST、セッションの改名・並行開発を開始・アーカイブ・アーカイブ解除・削除（確認付き）を長押しメニューから行えるようにする
- **FR-015**: アプリ MUST、選択中のエージェントのホーム（main のセッション）と、ピン留めしたセッションを履歴より上に出す。ピン留めしたセッションは履歴の一覧に重ねて出さず、長押しでピンを外せる
- **FR-016**: アプリ MUST、履歴の並べ方を「更新順 / 作業フォルダ別」から選べるようにし、エージェントごとに保持する。作業フォルダ別はフォルダを親にしたツリーで、フォルダごとに開閉できる
- **FR-017**: アプリ MUST、サイドパネルに出すエージェントの並びと表示する・しないを設定で変えられるようにする。同時に出すのは最大 4 体
- **FR-018**: アプリ MUST、会話の画面の右上のピルから、セッションのメニュー（名前を変更・ピン留め、区切って ファイル・ターミナル・並行開発を開始・変更量）を開けるようにする。新しいチャット（セッションがまだ無い）ではファイル・ターミナルだけを出す
- **FR-019**: アプリ MUST、作業フォルダの Git の変更量（合計の追加・削除の行数と、ファイルごとの内訳・差分）を見られるようにする。メニューには合計を添える
- **FR-014**: 大画面ではアプリ MUST、サイドバーとチャットを 2 ペインで同時に表示する

**チャット**

- **FR-020**: アプリ MUST、選択したセッションの会話履歴を表示し、古い履歴は遡るにつれて読み込む
- **FR-021**: アプリ MUST、メッセージを送信し、エージェントの応答を届いた分から順に表示する
- **FR-022**: アプリ MUST、生成中の応答を停止できるようにする
- **FR-023**: アプリ MUST、Markdown（見出し・リスト・表・コード）を整形して表示し、コードは等幅で表示する
- **FR-024**: アプリ MUST、ツールの実行を折りたたみ可能な行として表示する
- **FR-025**: アプリ MUST、応答ごとに日時・返信（引用して入力欄へ）・コピーの操作を提供する（共有は置かない。2026-11-23）
- **FR-026**: アプリ MUST、画像を添付して送信できるようにし、会話中の画像は全画面オーバーレイで表示する
- **FR-027**: アプリ MUST、Gateway が承認を求めたときに承認・拒否を操作できるようにする
- **FR-028**: アプリ MUST、セッションごとの入力中の下書きと読んでいた位置を、アプリの終了を越えて保持する
- **FR-029**: アプリ MUST、入力欄のマイクから Android 組み込みの音声認識で文字を入力できるようにする。結果は入力欄に入れるだけで自動送信しない（聞き取り中の行に、やめる・声の大きさの波形・終える・終えて送信を出す。送るのは「終えて送信」を押したときだけ）。端末に音声認識が無い場合はマイクを出さない

**セッション作成**

- **FR-030**: アプリ MUST、新規チャットの操作から新しいセッションを作成できるようにする
- **FR-031**: アプリ MUST、新規セッションの作成時に、直近に使った作業フォルダ（5 つまで）か、Gateway ホスト上を辿ったフォルダを作業フォルダに指定できるようにする。未指定ならエージェントの既定を使う
- **FR-032**: アプリ MUST、新規セッションの空の会話に、選んでいる作業フォルダ名をチップで示す（押すとフォルダ選択）。作成後のセッションのヘッダには作業フォルダ名を出さない（2026-11-23。作業フォルダは履歴の作業フォルダ別の表示で分かる）
- **FR-033**: アプリ MUST、Git の作業フォルダのセッションから、ワークツリーで作業を分けた新しいセッション（並行開発）を作れるようにする。ブランチ名（空なら Gateway が会話のタイトルから決め、重なれば番号を付ける）・元にするブランチ（Gateway が返す一覧から選ぶ。初期値は今のブランチ。一覧が取れなければ自由入力）・会話を引き継ぐかを選べる
- **FR-034**: 並行開発で手入力したブランチ名が既にあるブランチと重なるとき、アプリ MUST、作る前に重なりを示して作成させない

**チャットの補助**

- **FR-035**: 生成中に送ったメッセージ MUST、実行に差し込む（steer）。取り込まれるまでは入力欄の上に待ちの行を出し、取り消しと入力欄への戻しを選べるようにする
- **FR-036**: アプリ MUST、入力欄で `/` のコマンドと `$` のスキルを、Gateway が公開する一覧から補完できるようにする（説明はアプリの言語で）
- **FR-037**: アプリ MUST、エージェントからの質問（`ask_user`）に、1 問ずつ選択肢か自由入力で答えられるシートを出す。閉じたら入力欄の上から開き直せる
- **FR-038**: アプリ MUST、会話の中のリンクを押すとアプリ内で開き、長押しでコピー・ダウンロード・ブラウザで開くを選べるようにする。動画・画像のリンクはアプリ内の全画面で見せる
- **FR-039**: アプリ MUST、引用（吹き出しの文字を選んで「プロンプトに入力」。長さに関係なく）とコピーしたテキスト（100 文字以上で改行を含む貼り付け）を、画像と同じ添付の列にタイルで並べる。タイルを押すと全文のプレビュー（引用は本文の文字、コピーしたテキストは等幅）と「外す」「入力欄に戻す」を出す。貼り付けた直後は「入力欄に戻す」で文字に戻せる。送るとき、引用は本文の前に Markdown の引用、コピーしたテキストは `.txt` の添付にする（新しいチャットの最初の 1 通だけは本文の後ろ）（2026-11-26）

**通知**

- **FR-100**: アプリ MUST、アプリがバックグラウンドまたは閉じているときに、エージェントの応答の完了を通知する
- **FR-101**: 通知 MUST、エージェント名・セッション名・応答の内容（長ければ冒頭）を含む
- **FR-102**: 通知 MUST、エージェントごとにまとめ、エージェントごとにオン・オフと通知音を端末の設定で変えられるようにする
- **FR-103**: 通知を開くと、アプリ MUST、そのセッションの該当する応答の位置を開く
- **FR-104**: アプリ MUST、通知から直接返信できるようにし、送信の結果を通知に示す
- **FR-105**: マスターがそのセッションを画面で開いているとき、アプリ MUST NOT、その応答を通知しない
- **FR-106**: アプリ MUST、Gateway の承認待ちと自動化の失敗も通知する（種類ごとにオン・オフできる）
- **FR-107**: 同じセッションの通知 MUST、1 つにまとめて更新する
- ~~**FR-108**~~: 2026-11-26 削除（006 FR-032 に合わせる）。ロック画面での表示は端末の設定に任せる
- **FR-109**: アプリ MUST、バックグラウンドの接続の状態を設定画面で示し、端末の電池の最適化で止められている場合はその旨と解除の導線を出す
- **FR-120**: アプリ MUST、通知を受けるための常駐（常時接続。常駐の通知を伴う）を設定でオン・オフできるようにする。初期値はオフ（2026-11-26 改訂。詳細は 006 FR-003）
- **FR-121**: アプリ MUST、通知のテスト（端末内で通知を出す確認）を設定画面から行えるようにする
- **FR-122**: アプリが裏にあるあいだ、アプリ MUST、Gateway から受け取るイベントを通知に要るもの（応答の完了・承認待ち・自動化の失敗）に絞り、応答を文字ごとに流すイベントは受け取らない。画面に戻ったら差分を取り直す

**モデル・エフォート・使用量**

- **FR-040**: アプリ MUST、セッションのモデルを Gateway が公開する一覧から選んで変更できるようにする
- **FR-041**: アプリ MUST、選択中のモデルが公開するエフォートの選択肢だけを表示し、選んだ値をセッションに適用する
- **FR-042**: アプリ MUST、セッションのコンテキストウィンドウの使用量（使用量・上限・割合）を表示する
- ~~**FR-043**~~: 2026-11-25 削除。セッションのシートから最新の実行の入力・出力トークンの行を外した（生成中の出力トークンは推論中の表示に出す）
- **FR-044**: アプリ MUST、プロバイダが報告する使用枠（枠の名前・割合・枠が戻る時刻）を表示する
- **FR-045**: 使用量の一部が取得できないとき、アプリ MUST、その部分だけを取得できない状態として示し、他の表示を妨げない
- **FR-046**: アプリ MUST、セッションの権限（`permissionMode`）を Gateway が公開する選択肢から選んで変更できるようにする。選ぶ場所は入力欄の実行権限のボタン（今の段階のアイコン。2026-11-26 にセッションのシートから移した）
- **FR-047**: アプリ MUST、入力欄のモデルのピルに、使ったコンテキストの分だけ塗りを伸ばして示し、押すとセッションのシート（「モデル」の節にモデル・エフォートの選択とコンテキストウィンドウ、続いてプロバイダの使用量・リソース）を開く。ピルの幅はモデル名の長さに合わせ、文字はアプリの文字サイズに連動させない（2026-11-26 改訂。以前は色で示し、シートに権限もあった）
- **FR-048**: アプリ MUST、セッションのシートにコンテキストの内訳（メッセージ・ファイル・ツール・スキル・システム）を示す

**ファイルビューア**

- **FR-050**: アプリ MUST、セッションの作業フォルダとエージェントのワークスペースのファイルを一覧で辿れるようにする
- **FR-051**: アプリ MUST、テキストファイルを等幅・色分けで表示し、編集して Gateway に保存できるようにする
- **FR-052**: アプリ MUST、保存時に Gateway 側の変更との衝突を検出して示す
- **FR-053**: アプリ MUST、ファイルを端末のダウンロード先に保存できるようにする
- **FR-054**: アプリ MUST、画像ファイルを全画面オーバーレイで表示する

**ターミナル**

- **FR-060**: アプリ MUST、Gateway ホスト上の対話的なターミナルを開き、入力と出力をやり取りできるようにする
- **FR-061**: アプリ MUST、ソフトウェアキーボードに無い特殊キー（Ctrl・Esc・Tab・矢印）を送る手段を提供する
- **FR-062**: アプリ MUST、Gateway がターミナルを許可していないとき、理由を示して開かない

**Gateway の再起動**

- **FR-070**: アプリ MUST、Gateway の再起動を 1 つのボタンから指示できるようにする
- **FR-071**: アプリ MUST、再起動の前に確認ダイアログを出す
- **FR-072**: アプリ MUST、再起動中→再接続中→接続済みの状態を示し、再接続後に元の画面と状態へ戻る
- **FR-073**: アプリ MUST、再起動の指示を重複して送らない

**自動化（cron）**

- **FR-110**: アプリ MUST、Gateway に登録された自動化を、名前・対象のエージェント・スケジュール・有効か無効か・次の実行時刻・前回の結果とともに一覧表示する
- **FR-111**: アプリ MUST、自動化を作成・編集できるようにする。スケジュールは日時指定（一度きり）・一定間隔・cron 式（タイムゾーン指定付き）に対応する
- **FR-112**: アプリ MUST、自動化の有効・無効を切り替えられるようにする
- **FR-113**: アプリ MUST、自動化を今すぐ実行できるようにする
- **FR-114**: アプリ MUST、確認ダイアログを経て自動化を削除できるようにする
- **FR-115**: アプリ MUST、自動化の実行履歴（結果・所要時間）を表示し、実行で生まれた会話を開けるようにする
- **FR-116**: アプリ MUST、cron 式の誤りを保存前に示し、正しい式では次の実行予定を示す
- **FR-117**: 自動化の実行で生まれた会話 MUST、通常のセッション一覧と分けて表示する

**テーマ**

- **FR-080**: アプリ MUST、外観（システム / ライト / ダーク）を選べるようにする
- **FR-081**: アプリ MUST、テーマを OpenClaw・Monochrome・ダイナミック・カスタムの 4 つから、外観と独立に選べるようにする。初期値は OpenClaw。各テーマに短い説明を添える
- **FR-082**: アプリ MUST、浮いている面の透かし方（ガラス / ぼかし）を選べるようにする。初期値はガラス。選んだ透かし方の強さ（ガラスの屈折・ぼかしの強さ）を 0〜10 の 10 段階で変えられるようにする（不透明度は変えない）
- **FR-084**: OpenClaw テーマ MUST、OpenClaw の Web UI と同じ赤を基調にする
- **FR-085**: Monochrome テーマ MUST、モノクロを基調にし、強調・リンク・エラーは明度の差や形で判別できるようにする（エラーの色だけは残す）
- **FR-086**: ダイナミックテーマ MUST、端末の壁紙の色から配色を作る
- **FR-087**: カスタムテーマ MUST、マスターが指定した色（RGB のスライダーとカラーコード）から配色を作り、指定した色の明るさを保つ（白や灰色を指定して色が付かない）
- **FR-088**: どのテーマでも、文字と背景のコントラスト MUST WCAG AA 以上を保つ
- **FR-083**: アプリ MUST、テーマの変更を即座に反映し、終了を越えて保持する
- **FR-089**: アプリ MUST、表示のフォント（LINE Seed JP / システム。初期値は LINE Seed JP）と文字の大きさを設定で選べるようにする

**体験（動きとデザイン）**

- **FR-090**: すべての画面遷移・開閉・切り替え MUST、`AGENTS.md` 2.8 の動きの規則に従い、動きの途中でも次の操作を受け付ける
- **FR-091**: 画面の上に浮く面（上部のピル・ボタン・入力ピル・シート・メニュー・Snackbar）MUST、背後の内容を透かすガラス表現で描く
- **FR-092**: アプリ MUST、予測型「戻る」に対応し、戻るジェスチャーの途中で前の画面がのぞく
- **FR-093**: アプリ MUST、Android 13 以上で動作する
- **FR-094**: 利用者向けの文言 MUST、日本語と英語に対応し、アプリ単位の言語設定に従う

### Key Entities

- **Gateway 接続**: 接続先・ゲートウェイトークン・接続状態。アプリは 1 つの Gateway に接続する
- **エージェント**: 名前・アバター・既定のモデル・既定の作業フォルダ。複数のセッションを持つ
- **セッション**: タイトル・所属エージェント・作業フォルダ・モデル・エフォート・権限・状態（実行中・未読・アーカイブ・ピン留め・ホーム）・コンテキスト使用量・親のセッション（並行開発で分けたもの）
- **サイドパネルの表示設定**: 表示するエージェントの並びと表示する・しない（最大 4 体）、エージェントごとの履歴の並べ方。端末内に保持
- **メッセージ**: 送信者（利用者・エージェント）・本文・添付・ツールの実行・時刻
- **使用枠**: プロバイダ・枠の名前（5時間・週など）・割合・枠が戻る時刻
- **ファイル**: パス・種類・大きさ・更新時刻・内容
- **ターミナル**: 開始フォルダ・入出力の流れ・生存状態
- **通知設定**: エージェントごとのオン・オフ、種類（応答・承認待ち・自動化の失敗）ごとのオン・オフ、ロック画面での表示。端末内に保持
- **自動化**: 名前・対象のエージェント・スケジュール（種類と値・タイムゾーン）・依頼内容・有効か無効か・次の実行時刻
- **自動化の実行**: 開始時刻・結果・所要時間・実行で生まれた会話
- **テーマ設定**: 外観（システム / ライト / ダーク）・テーマ（OpenClaw / Monochrome / ダイナミック / カスタム）・カスタム色・透かし方（ガラス / ぼかし）と強さ・フォント・文字の大きさ。端末内に保持

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初回の接続設定からメッセージの送信まで、3 分以内に完了できる
- **SC-002**: 起動からセッション一覧の表示まで、通常の回線で 2 秒以内
- **SC-003**: エージェントのタブ切り替え・サイドバーの開閉・画面遷移で、操作から 100ms 以内に動きが始まり、中位機種で目に見えるコマ落ちが無い
- **SC-004**: 1,000 メッセージを超える会話でも、スクロールが途切れずに追従する
- **SC-005**: 動きの途中での連打・取り消し・予測型「戻る」の途中停止で、表示の飛び・ちらつき・操作不能が 1 件も起きない
- **SC-006**: モデル・エフォート・使用量の表示値が、同時刻の Web UI の表示と一致する
- **SC-007**: Gateway の再起動を指示してから、通常 60 秒以内に再接続し、元のセッションを操作できる
- **SC-008**: アプリを強制終了して再度開いたとき、選択中のエージェント・セッション・下書き・読んでいた位置の 100% が復元される
- **SC-009**: ライト / ダーク × スマホ / タブレット × 文字 100% / 200% のすべてで、文字の切れ・重なりが無い
- **SC-010**: アプリを閉じた状態で、応答の完了から通知の表示まで、通常 5 秒以内
- **SC-011**: 24 時間の待ち受けで、応答の完了の 99% 以上が通知される（常駐オン・電池の最適化から外した状態）
- **SC-012**: 自動化の作成（新規から保存まで）を 1 分以内に完了できる
- **SC-013**: 常駐による電池の消費が、24 時間の待ち受けで端末全体の 3% 以下

## Assumptions

- Google Play ストアで公開する。利用者はそれぞれ自分の Gateway に接続する（開発・検証はマスターの Gateway で行う）
- 利用者は自分の Gateway に、ローカルネットワークまたは Tailscale 等の経路で到達できる
- 初回接続はゲートウェイトークン（Gateway の共有トークン）の入力で行う。QR やセットアップコードによるペアリングは v1 では作らない。Gateway が端末の承認を求めた場合は、承認待ちであることを示し、Web UI での承認後に接続を続ける
- テーマの仕組み（配色の生成、無彩色の扱い、背景の色寄せ、ガラスとぼかしの切り替え）は Gerbil（`~/Dev/workspace/boards`）の実装を参考にする。不透明度は `AGENTS.md` 2.10 の固定値に従う。透かしの強さ（屈折・ぼかし）は Gerbil と同じく 10 段階で調整できる（2026-11-22 マスター指定で変更）
- データとプロトコルは OpenClaw Gateway が Web UI（Control UI）に提供しているものを使う。セッション・会話・モデル・使用量・再起動は Gateway が提供済み。ターミナルとファイル操作の提供範囲は plan で実装を確かめ、無い部分はその時点で範囲を決め直す
- ファイルビューアとターミナルの権限は Gateway の設定に従い、アプリ側で広げない。対象はセッションの作業フォルダとエージェントのワークスペースを既定とする
- 再起動は Gateway 自身の再起動機能（ホストのサービス管理による復帰）を使い、アプリが SSH 等で直接ホストを操作しない
- 通知は OpenClaw 公式 Android アプリと同じ方式にする。アプリは常駐の通知（Android のフォアグラウンドサービス）を出して Gateway との接続を保ち、Gateway から届くチャットのイベントをもとに端末内で通知を作る。外部の中継サーバー・Push サービス・Gateway のプラグインは使わない
- 常駐（常時接続）は設定でオン・オフできる（初期値はオフ。2026-11-26 改訂）。オフにすると、アプリを開いているあいだ（と裏に回って 60 秒以内）だけ通知と更新が届く
- 常駐の通知は目立たない重要度で出し、接続の状態（接続済み・再接続中）だけを示す
- Gateway は接続の生存確認（WebSocket の ping）を 25 秒ごとに送る（ローカルのソースで確認。アプリ側では変えられない）。v1 はこれを受け入れ、電池の消費は購読するイベントを絞って抑える。実機の計測で SC-013 を超えた場合は、モバイル回線のときだけ裏では定期的につなぎ直して確認する方式を追加で検討する
- Play ストアの審査では、フォアグラウンドサービスの用途の申告が要る。用途の種類は plan で決める（公式アプリは connectedDevice を宣言している）
- 自動化の管理は Gateway の自動化機能（定期実行・一度きり・cron 式）を対象にし、コマンドの終了やストリームを契機にする高度な種類は一覧で表示するだけにする（作成・編集は v1 の範囲外）
- 音声入力は Android 組み込みの音声認識で文字にするだけにする（Gateway 側の音声機能は使わない）
- リアルタイム通話、チャンネル・プラグインなどの管理画面は v1 の範囲外
- Web UI の設定画面全体は再現しない。アプリの設定は接続（と再起動）・エージェントの表示・表示（外観・テーマ・フォント・透過効果）に限る。言語は Android のアプリ単位の言語設定に従う
- 見た目と動きの細則は `AGENTS.md` を正とし、本仕様は ChatGPT 型の骨格（右上に浮くピル、右寄せの利用者メッセージ、全幅の応答、下部に浮く入力ピル）を前提とする。ただし色・アイコン・部品は ChatGPT ではなく Material 3 と Hugeicons で作る
